# 部署指南

适用服务器 `82.157.137.114`（Ubuntu 22.04 / MySQL 8.0.46 / Node 22 / Java 17 / PM2 / Nginx）。2026-09-15 编写。

---

## 1. 服务架构

```
Nginx :4001/:4002
  /user/           → 用户端 H5 静态产物
  /                → 商家端静态产物
  /demo/           → 互动汇报页
  /user/api/  ─┐
  /api/       ─┤→ 127.0.0.1:4000/api/   (Spring Boot)
  /uploads/     → 127.0.0.1:4000/uploads/

Spring Boot :4000 (仅 127.0.0.1)
MySQL :3306 (业务库 elm_practice / 测试库 elm_practice_test)
```

| 服务 | 地址 |
| --- | --- |
| 用户端 | http://82.157.137.114:4001/user/ |
| 商家端 | http://82.157.137.114:4001/ |
| 互动汇报 | http://82.157.137.114:4001/demo/ |
| 后端 | 127.0.0.1:4000（Nginx 代理，不对外暴露） |

## 3. 数据库

**业务库** `elm_practice`：线上运行数据，禁止执行重置类脚本。

**测试库** `elm_practice_test`：每用例前 `reset.sql` 复位，仅在此库跑测试。

建表与种子由 `DatabaseInitializer` 在后端启动时自动执行（幂等）：先 `schema.sql` 建表，再各 `upgrade-*.sql` 迁移，仅当 users 表为空时执行 `seed.sql` 插种子，最后执行 stage3 数据种子（会员标记、课程分类、收藏、通知）。首次部署只需启动后端即可自动建库。

SQL 真源：`backend/database/schema/schema.sql` 与 `backend/database/seed/seed.sql`；`backend/src/main/resources/db/` 下为打包副本，同源双写。

## 4. 构建

### 4.1 用户端

```bash
cd frontend/user-h5
npm ci
npx vitest run
npm run type-check
VITE_API_MODE=real VITE_API_BASE_URL=/user/api/v1 npx vite build --base=/user/
```

产物 `dist/` → 汇集到 `www/user/`。

### 4.2 商家端

```bash
cd frontend/merchant-admin
npm ci
npm test
VITE_API_MODE=real VITE_API_BASE_URL=/api/v1 npm run build
```

产物 `dist/` → 汇集到 `www/merchant/`。

### 4.3 后端

```bash
cd backend
export DB_HOST=82.157.137.114 DB_USER=elm DB_PASSWORD=<密码> DB_NAME=elm_practice_test
mvn -B test                  # 测试（连测试库）
mvn -B -DskipTests clean package  # 打包
```

产物 `target/elm-practice-backend-0.1.0-SNAPSHOT.jar`。

> Windows 构建前须停 4000 端口进程，否则 `clean` 因文件锁失败：
> `Get-NetTCPConnection -LocalPort 4000 -State Listen | %{ Stop-Process -Id $_.OwningProcess -Force }`

### 4.4 汇集静态产物

```bash
mkdir -p www/user www/merchant www/demo
cp -r frontend/user-h5/dist/. www/user/
cp -r frontend/merchant-admin/dist/. www/merchant/
cp -r docs/presentation/. www/demo/
```

## 5. 发布

### 前置清单

- 源码目录含 `www/`、`deploy/nginx.conf`、`backend/target/*.jar`
- 备份目录含 `pm2-before.json`（PM2 配置快照，凭据从此读取）
- `backend/uploads/` 目录存在且运行用户可写
- `DEEPSEEK_API_KEY` 已在 PM2 环境中配置

### 发布命令

```bash
ssh <账号>@82.157.137.114
cd /home/ubuntu/releases/elm-<tag>

python3 deploy/release.py \
    --source /home/ubuntu/releases/elm-<tag> \
    --tag <tag> \
    --release-sha <commit-sha> \
    --backup /home/ubuntu/backups/elm-<backup-tag>
```

> 不带参数运行 = 按默认值发布 2026-09-08 首版（等价于回滚到旧版）。正式发布必须显式传全部参数。

### 脚本流程

1. 前置校验（www/nginx.conf/pm2-before.json/jar），缺失即退出不触碰现网
2. 从 `pm2-before.json` 提取 `DB_*`，若含 `DEEPSEEK_API_KEY` 则一并继承
3. 拷贝 www → `/srv/elm-releases/<tag>`，切换 `/srv/elm-current` 软链
4. 生成 Nginx 配置到 `/etc/nginx/conf.d/elm-release.conf`
5. `nginx -t` → 重启 `elm-backend` → 探活 `http://127.0.0.1:4000/api/v1/stores`
6. 退役旧前端 PM2 条目 → reload nginx → 验证 `:4001/` 全 200 → `pm2 save`

失败自动回滚：删 nginx 配置 → reload → 删新 backend → 从 backup 恢复。

### 目录结构

```
/srv/elm-releases/<tag>/         # 静态发布根（每版本子目录）
  ├── user/  merchant/  demo/
/srv/elm-current -> <tag>        # 软链指向当前版本

/home/ubuntu/releases/elm-<tag>/ # 源码与构建产物
  ├── backend/target/*.jar
  ├── deploy/
  └── www/

/home/ubuntu/backups/elm-<tag>/  # 回滚资产
  ├── pm2-before.json
  └── restore-*.json
```

## 6. 验证

```bash
python3 deploy/smoke.py          # 核心业务链路冒烟
sudo nginx -t
curl -f http://127.0.0.1:4001/user/api/v1/stores
curl -f http://127.0.0.1:4001/demo/
```

`smoke.py` 验证注册→登录→开店→商品→加购→下单→支付→状态机推进→完成的完整链路，金额按契约 §3.5 公式核对。产物 `deploy/smoke-result.json` 提交到仓库。该脚本会创建合成数据，非只读，重复运行会新增记录。

## 7. 回滚

```bash
pm2 delete elm-backend
pm2 start /home/ubuntu/backups/elm-<backup-tag>/restore-backend.json
pm2 start /home/ubuntu/backups/elm-<backup-tag>/restore-frontends.json
sudo ln -sfn /srv/elm-releases/<旧tag> /srv/elm-current
sudo nginx -t && sudo systemctl reload nginx
pm2 save
```

正常只回滚应用，不回灌数据库（保留发布后的订单数据）。

## 8. 安全约定

- MySQL 密码、SSH 密码、`DEEPSEEK_API_KEY` 不入仓库、不入文档、不发群聊
- PM2 JSON 配置权限 600，不含明文密码
- 后端 4000 仅监听 127.0.0.1，不对外暴露
- 安全组 TCP 3306 已放行（建议收紧到团队出口 IP）
- 测试只在 `elm_practice_test` 执行，禁止对业务库执行重置类测试
