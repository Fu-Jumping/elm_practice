# 测试计划

日期：2026-09-04  
负责人：测试联调同学（成员D（商家端/测试））  
依据：`docs/PRD.md`、`docs/project/TDD实施规划.md`、`docs/backend/后端接口契约.md`、`docs/SRS.md`

## 1. 测试目标与范围

目标是证明六类 P0 能力在真实接口、数据库和前端真实模式下可运行、可解释、可回归：用户、商家、店铺、商品/分类、购物车、地址与基础订单。核心闭环为：

`注册/登录 → 浏览店铺与商品 → 加购/修改购物车 → 选择地址 → 创建订单 → 查询订单列表与详情`

本阶段同步覆盖商家端 P0：商家登录、当前店铺、店铺资料与营业状态、分类管理、商品管理、商家订单列表/详情。

**本期范围（2026-09-09 第二阶段范围决议，负责人拍板）**：除平台管理员外，全部 P1 与 P2 纳入本期测试范围（**本期实现，待开发**）——模拟支付与库存一致性、商家订单推进与跨端同步、优惠与后端统一计价、评价与商家回复、用户与商家消息、搜索排序与分页、商家收藏、会员权益、红包、商品规格扩展、待支付倒计时、再来一单、评价订单、分类绑定商品，以及简化取消订单、~~简化配送管理~~（已砍，CHG-002）、图片上传、设置与 FAQ；商家端原标注“二期不做”的 7 页（运营概览、优惠配置、评价管理、评价回复、消息列表、聊天详情、数据统计）与规格维护、联系顾客同期纳入，否则优惠/评价/消息/统计无法形成双端闭环。**平台管理员砍掉**，不制作页面、接口、数据与测试，不作为交付内容。以上扩展在 P0 全绿后分批执行红-绿，未收口模块一律标注“待实现”、证据字段写“待补”；老师下发的阶段 2 需求变更内容尚未发布（2026-09-10 起按「待定」跟踪：负责人判断大概率不发布，不作为开发前置阻塞），本组决议不替代老师变更。

## 2. 测试策略

| 层级 | 检查内容 | 主要方式 | 通过证据 |
| --- | --- | --- | --- |
| 后端 Service 单元 | 字段边界、业务规则、状态和归属 | JUnit 5 + Mockito | 正常与异常用例全绿 |
| 后端接口集成 | HTTP 状态、统一 JSON、Session、权限、数据库结果 | MockMvc 或 TestRestTemplate | 请求/响应和数据库核对记录 |
| 前端适配与交互 | 真实模式、401 跳转、金额/状态展示、表单和购物车交互 | 用户端 Vitest；商家端 Vitest + RTL | 测试输出与页面复现记录 |
| 跨端联调 | 用户下单后商家可查、状态/库存/快照一致 | 关闭 Mock 回退的浏览器操作 + 接口日志 | 联调记录、截图或录屏 |
| 回归与验收 | 已修复缺陷、需求变更、P0 主链路 | 固定数据重置后重跑 | 回归记录与缺陷状态 |

统一断言：成功响应为 `code=0` 且包含 `message`/`data`；失败响应为 JSON，HTTP 状态符合契约，不能返回 HTML；金额以后端计算为准；时间为东八区 `yyyy-MM-dd HH:mm:ss`；身份从 Session 读取。

## 3. 执行顺序与硬门槛

1. **9/4：第一批失败测试先行。** 测试类/接口测试必须先提交并保留首次失败输出，提交类型为 `test:`；实现或修复提交只能在其后使用 `feat:` 或 `fix:`。今天不得先写实现再补测试，也不得用跳过测试制造“绿色”。
2. 9/5：先完成账号、权限、商家注册、分类和商品管理的红-绿循环。
3. 9/6：完成店铺查询与购物车，并验证跨商家隔离和异常边界。
4. 9/7：完成地址、订单创建/查询、商家订单页；设置 `VITE_MOCK_FALLBACK=false`，执行真实 P0 全链路与回退检查。
5. 9/8 或 9/9 中期验收后：本组第二阶段范围决议（2026-09-09）已落定，除平台管理员外全部 P1/P2 纳入本期；扩展模块在 P0 全绿后分批启动，每批先新增失败测试，再实现、修复并回归；老师下发的变更内容到达后走同一流程。
6. 9/9–9/14：扩展分批红-绿（按模块批次先 `test:` 后 `feat:`，每批以“接口 + 数据库 + 测试 + 页面”四类证据收口）；9/14 执行总回归；9/15 做冻结前回归；9/16 执行交叉验收。

一个模块的通过条件：接口级用例全部执行；正常和异常均通过；至少覆盖相关 `400/401/403/404/409` 语义；统一响应、权限归属、数据库影响和前端结果均有证据；缺陷没有未评审的 P0/P1 阻塞项。

## 4. 环境与数据

- 后端默认：`http://127.0.0.1:4000`；接口前缀：`/api/v1`。
- 真实联调（PowerShell 赋值，**等号两侧不留空格**，与契约 §8 写法一致）：`$env:VITE_API_MODE="real"`、`$env:VITE_API_BASE_URL="http://127.0.0.1:4000/api/v1"`、`$env:VITE_MOCK_FALLBACK="false"`。
- 固定演示数据：用户 `13800000001 / 123456`；商家 `merchant-a / 123456`；主店铺 `m002`；地址为天津大学北洋园校区 12 号楼 304 室；主店铺至少 5 个商品。
- 每轮集成测试前重置测试库或使用唯一测试账号；用例不得依赖执行顺序。不得把真实数据库密码写入测试记录。

## 6. 暂定项

店铺关闭加购、不满足起送条件、分类有商品删除等场景的最终 `400/409` 归属以 SRS 定稿为准；在定稿前用例只判断“请求被拒绝、无脏数据、页面给出可理解提示”，定稿后回填精确状态码。数据库统一使用服务器测试库 `elm_practice_test`（`DB_NAME=elm_practice_test`，见项目规则 §5 2026-09-10 R8 定稿与运行说明 §4.5），本机不装 MySQL，接口层断言保持不变。本期扩展的取消订单、图片上传、收藏、红包、会员等接口路径与错误码以接口契约补充后为准，补充前只判断“请求被拒绝、无脏数据、页面给出可理解提示”，并按“待实现”标注；配送进度由订单状态 `DELIVERING` 表达，不另设接口（CHG-002）。
