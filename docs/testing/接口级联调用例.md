# 接口级联调用例

日期：2026-09-04  
用途：从接口契约生成可执行的接口/集成联调清单。测试数据每轮执行前重置；实际 HTTP 状态、响应体、数据库结果和页面证据填写到联调记录，不以 Mock 结果代替。

## 1. 执行约定

- 服务地址：`http://127.0.0.1:4000/api/v1`；Session Cookie 必须在同一角色链路中持续携带。
- 真实模式：`VITE_API_MODE=real`、`VITE_API_BASE_URL=http://127.0.0.1:4000/api/v1`、`VITE_MOCK_FALLBACK=false`。
- 每条用例记录：请求前置 → 请求方法/路径/体 → HTTP 状态 → JSON `code/message/data` → 数据库影响 → 页面结果 → 清理方式。
- 失败响应必须是 JSON；出现 HTML、静默 Mock 回退、跨用户/跨店数据泄露、半成功事务均判失败。
- 契约尚未固化的具体状态码按“拒绝请求 + 无脏数据 + 可理解提示”验收，SRS 定稿后补精确码。

## 2. 用户端级联用例

### 2.1 账号与会话（IC-ACC）

| 编号 | 前置与操作 | 请求链 | 关键断言 |
| --- | --- | --- | --- |
| IC-ACC-01 | 新手机号注册 | `POST /users` `{account,password,nickname}` | `2xx`、`code=0`；返回用户摘要，不含密码；可登录 |
| IC-ACC-02 | 使用 10 位/12 位/含字母手机号注册 | 分别 `POST /users` | `400` JSON，指出账号格式；数据库不新增 |
| IC-ACC-03 | 使用已注册账号注册 | `POST /users` | `409`；原账号数据不变 |
| IC-ACC-04 | 使用少于 6 位或超过 20 位密码注册 | `POST /users` | `400`；不落库 |
| IC-ACC-05 | 合法用户登录 | `POST /auth/login` `{account,password,role:user}` | `2xx`、`code=0`、`Set-Cookie`；随后 `GET /me` 返回当前用户 |
| IC-ACC-06 | 错误密码、未知账号、role 非 user | `POST /auth/login` | 错误密码/未知账号 `401`；非法字段按契约为 `400`；不泄露账号存在性 |
| IC-ACC-07 | 注销并访问受保护资源 | `POST /auth/logout`；再 `GET /me`、`GET /cart` | 注销成功；后续均 `401` |
| IC-ACC-08 | 用户调用商家接口 | 用户 Session 请求 `GET /merchant/me` | `403`，不返回商家数据 |
| IC-ACC-09 | 修改当前用户资料 | `GET /me` → `PATCH /me` → `GET /me` | 只修改允许字段；返回值与再次查询一致；伪造 `userId` 不改变归属 |

### 2.2 店铺、商品与购物车（IC-BROWSE/IC-CART）

| 编号 | 前置与操作 | 请求链 | 关键断言 |
| --- | --- | --- | --- |
| IC-BROWSE-01 | 查询首页店铺 | `GET /stores` | `code=0`；无结果为 `data: []`；过滤/排序参数生效 |
| IC-BROWSE-02 | 查询 m002 详情、分类、商品 | `GET /stores/m002` → `/stores/m002/categories` → `/stores/m002/products` | 数据均属于 m002；店铺 status 合法；用户端下架商品不可购买 |
| IC-BROWSE-03 | 查询不存在店铺/商品 | `GET /stores/unknown`、`GET /products/unknown` | `404` JSON；页面清空旧详情并展示空态 |
| IC-BROWSE-04 | 合法商品加入购物车并重复加入 | `POST /cart/items` 两次 → `GET /cart?storeId=m002` | 同一用户/店铺/商品只有一行，数量合并；价格以后端商品价为准 |
| IC-CART-01 | 修改数量、删除购物车行 | `PATCH /cart/items/{lineId}` → `DELETE .../{lineId}` → `GET /cart` | 数量和删除结果一致；数量为 0/负数请求 `400` 或按前端转删除 |
| IC-CART-02 | 超库存、下架商品、闭店加购 | 分别 `POST /cart/items` | 请求被拒绝，状态码按 SRS 固化；无新增/超量行；提示含处理建议 |
| IC-CART-03 | 未登录或操作他人行 | 无 Session 请求；用户 A 操作用户 B 的 `cartLineId` | 分别 `401`、`404`；不泄露行内容 |

### 2.3 地址与订单（IC-ADR/IC-ORD）

| 编号 | 前置与操作 | 请求链 | 关键断言 |
| --- | --- | --- | --- |
| IC-ADR-01 | 查询、创建、修改地址 | `GET /me/addresses` → `POST /me/addresses` → `PATCH /me/addresses/{id}` | 只返回当前用户；必填/电话非法为 `400`；默认地址最多一条 |
| IC-ADR-02 | 查询地址详情、删除默认地址和他人地址 | `GET /me/addresses/{id}` → `DELETE /me/addresses/{id}` | 详情只属于当前用户；删除默认后最近更新地址成为默认；无剩余则无默认；他人地址 `404` |
| IC-ORD-01 | 用户 m002 有购物车和地址，创建订单 | `POST /orders` `{storeId,addressId,remark,expectedTotal}` | 成功状态 `PROCESSING`；返回订单、商品/地址/金额快照；实付 = 商品小计 + `packagingFee`（2.00） |
| IC-ORD-02 | 创建后查询订单 | `GET /orders` → `GET /orders/{orderId}` → `GET /orders/{orderId}/items` | 列表倒序；详情与快照一致；购物车已清空 |
| IC-ORD-03 | 地址越权、店铺关闭、商品下架、库存不足、起送不足 | 分别 `POST /orders` | `404` 或 `409`/`400` 按契约/SRS；不生成半成品订单，购物车保持原状 |
| IC-ORD-04 | 前端金额被篡改、商品已改价 | 提交错误 `expectedTotal`；创建前修改商品价 | 以后端计算为准；旧订单金额快照不变 |
| IC-ORD-05 | 查询不存在/他人订单 | `GET /orders/{id}`、`GET /orders/{otherId}` | 均 `404` JSON；不返回订单信息 |
| IC-ORD-06 | 模拟事务失败 | 构造任一明细校验失败后查询订单、库存、购物车 | 订单、库存、购物车无半成功变化 |
