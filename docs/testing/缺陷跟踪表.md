## 1. 使用规则

- 编号递增且不复用：接口/业务缺陷使用 `BUG-YYYYMMDD-001`；展示问题可使用 `SHOW-QA-001`。
- **落盘要求（2026-09-08 新增）**：发现即在本表登记编号，并把明细落 `docs/testing/问题记录/YYYY-MM-DD-<主题>.md`；不得只发群聊、共享文档或本地归档（`docs/_archive/**` 已 gitignore）。群聊与口头只作通知，不作证据。
- **来源互链**：每条缺陷在"来源问题记录"与"证据/备注"字段填写对应文件名，问题记录文件头注明台账编号。
- 发现即登记，至少填写复现环境、前置数据、步骤、实际结果、期望结果和证据；没有截图时填写请求/响应摘要或日志位置。
- 严重程度：`P0` 主链路阻塞、白屏、金额/权限/数据严重错误；`P1` 核心功能可绕过或结果错误；`P2` 非主链路问题；`P3` 体验或文案建议。
- 状态流转：`新建 → 已确认 → 修复中 → 待回归 → 已关闭`；无法复现为 `待补充`，暂不处理为 `延期`，重复问题标记 `重复`。
- 缺陷修复若需要改代码，必须先补能失败的回归测试，提交顺序严格为 `test:` → `fix:`；不得删除、跳过或放宽原测试。
- 关闭条件：修复提交可定位、原步骤回归通过、相关模块和 P0 主链路回归通过；未关闭缺陷不得写成已完成。
- 明细落盘口径（2026-09-08，PR #36 评审跟进）：本批 BUG-001~012 明细暂以本表第 3 节详情区块为唯一载体，未拆分 `docs/testing/问题记录/**` 独立文件；是否对后续新缺陷启用问题记录明细文件，由测试联调同学（王馨琪）确认口径后回填本条。SHOW-QA 类展示问题沿用 main 上既有问题记录明细模式。
