# 问题记录目录（明细与证据落盘区）

日期：2026-09-08（新建，负责人拍板）。

> 本目录是问题记录 / 问题单的**正式落盘区**，纳入 Git 跟踪；唯一正式台账是 `docs/testing/缺陷跟踪表.md`。规则口径见 `docs/project/项目规则.md` §1.1，问题单字段见 `docs/project/小组协作与提交流程.md` §4。

## 1. 命名与落位

- 命名：`YYYY-MM-DD-<主题>.md`，主题用中文短语（如 `2026-09-08-用户端主链路巡检.md`），不加空格。
- 一份问题记录可包含多条问题；每条在文件头标注对应台账编号。
- 存量文件迁入时可保留原文件名，但须在文件头补日期、主题与台账编号，便于与台账互链。
- 截图、录屏等二进制证据不入库（见 `.gitignore` 的临时产物规则），以路径、请求响应摘要或日志位置在文件内记录。

## 2. 收录流程

1. 发现人在本目录新建文件，按第 3 节字段写清复现步骤与证据；
2. 测试联调同学核对后，在 `docs/testing/缺陷跟踪表.md` 分配编号并登记；
3. 问题记录文件头补"台账编号"，台账"来源问题记录"字段填本文件名，两者互相引用；
4. 修复与回归后回填结果，台账状态随之流转；
5. 群聊 / 共享文档只作通知，不替代本目录落盘。

## 3. 问题单字段（与协作流程 §4、缺陷表模板一致）

```text
编号：BUG-YYYYMMDD-001 或 SHOW-QA-001（由测试联调同学分配）
页面 / 接口：
路由：
视口 / 环境（后端地址、前端地址、浏览器或设备、提交号）：
前置数据（账号角色、店铺/商品/订单标识；不记录密码或密钥）：
操作步骤：
实际结果：
期望结果（依据 PRD / SRS / 接口契约，尽量给出行号）：
证据（截图、录屏、请求响应摘要、日志位置）：
严重程度：P0 / P1 / P2 / P3
是否阻塞 P0：是 / 否
发现日期 / 发现人：
责任人：
状态：新建 / 已确认 / 修复中 / 待回归 / 已关闭 / 待补充 / 延期 / 重复
```

> 严重程度口径：`docs/project/小组协作与提交流程.md` §4 的"必须修 / 可后置 / 仅建议"为展示同学口头分级，收录进台账时由测试联调同学映射为 `P0 / P1 / P2 / P3`（映射关系：必须修→P0–P1，可后置→P2，仅建议→P3）。

## 4. 与其他记录的关系

| 记录 | 承载什么 | 写权 |
| --- | --- | --- |
| 本目录 `问题记录/**` | 明细、复现步骤与证据 | 发现人起草，测试联调同学收录 |
| `docs/testing/缺陷跟踪表.md` | 编号、状态、责任人与修复/回归结果（唯一正式台账） | 测试联调同学 |
| `docs/record/raw/YYYY-MM-DD/` | 成员与 AI 代理的即时留痕片段 | 成员与 AI 代理 |
| `docs/record/daily/YYYY-MM-DD.md` | 只写编号或链接的汇总口径 | 次晨汇总智能体 / 组长 |

**禁止**只把问题发在群聊、共享文档、`docs/_archive/**`（已 gitignore）或个人目录——那些位置不构成过程证据。
