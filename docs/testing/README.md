# testing 文档目录（测试落位）

日期：2026-09-02（新建），2026-09-08 更新（问题记录与缺陷跟踪正式落盘规则）。本目录是测试文档资源的统一落位：测试联调同学（王馨琪）名下的测试交付物建在这里，便于集中查阅与归档。

## 1. 落位规则

| 产物 | 位置 | 说明 |
| --- | --- | --- |
| 测试计划 | `docs/testing/测试计划.md` | 一页纸即可；与 TDD 实施规划互补，不重复矩阵内容 |
| 接口级联调用例 | `docs/testing/接口级联调用例.md` | 从 `docs/backend/后端接口契约.md` 生成；自测格式与失败判定见契约第 8 章 |
| 集成 / 回归测试记录 | `docs/testing/`（按阶段命名，现有 `回归记录-2026-09-08.md`） | 每次回归一份，纳入 Git 跟踪 |
| 缺陷跟踪（唯一正式台账） | `docs/testing/缺陷跟踪表.md` | **纳入 Git 跟踪的正式台账**，写权归测试联调同学；编号、字段与状态流转见 `docs/project/项目规则.md` §1.1 |
| 问题记录 / 问题单（明细与证据） | `docs/testing/问题记录/YYYY-MM-DD-<主题>.md` | **发现即落盘**（不得只发群聊、共享文档或本地归档）；收录后登记台账编号，命名与模板见 `docs/testing/问题记录/README.md` |
| 交叉验收报告 | `docs/testing/`（9/16 双盲交叉验收时生成） | 双盲交叉验收产物 |

## 2. 不迁入本目录的既有文档（保持原位）

- `docs/project/TDD实施规划.md`：全组 TDD 总口径（红-绿-重构、Git 证据、用例矩阵），不只属于测试同学，留在 project/ 供全组引用。
- `docs/backend/后端联调验收用例.md`：后端联调入口文档之一（AGENTS.md 阅读清单），P0 场景与固定演示数据由组长保留；其"待补"的商家端 P0 场景由王馨琪确定落位后可写入本目录的接口级用例文件。
- `docs/record/**`：每日记录与 raw 片段，按记录规则留在原处。

## 3. 职责边界（同 `docs/project/分工与里程碑安排.md`）

- 王馨琪：本目录全部产物的创建与维护；测试计划、集成/回归组织、需求变更影响分析、缺陷跟踪、交叉验收材料；兼任商家端负责人（`frontend/merchant-admin/` 开发）。
- 开发同学仍为自己模块编写单元测试；测试同学不替别人写单测。
- 问题记录与缺陷跟踪表由王馨琪统一落盘与维护（2026-09-08 负责人拍板，规则见 `docs/project/项目规则.md` §1.1）；其他成员发现缺陷先按问题单格式提交（`docs/project/小组协作与提交流程.md` §4），不得只口头反馈或只发群聊。
