# 小组协作与提交流程

日期：2026-09-01；2026-09-08 修订 §4 问题单提交位置（正式落盘 `docs/testing/**`，群聊仅通知，见 `docs/project/项目规则.md` §1.1）。

## 1. 协作原则

本项目当前处于从零开发、文档先行阶段；本次完成度以需求、测试、真实接口、数据库和 Git 记录为准。后续重点是让产品、前端、后端和测试/联调按同一套规则协作，避免互相覆盖、重复开发或把未确认内容带入演示。

核心原则：

- 组长保留主分支合并权和最终口径控制权。
- 后端同学在本仓库 `backend/` 目录维护后端工程，不把 Java 工程塞进前端工程目录。
- 展示同学可以发现问题、整理截图、补充演示材料；如需改代码，必须走分支和 PR。
- 所有问题优先按“复现步骤 + 截图/录屏 + 期望结果”记录，不凭口头描述直接改。
- 平台客服、真实支付、复杂权限、多商户组织后台不进入当前阶段。
- 普通品牌强调色继续统一为亮橙 `#ff5a1f`，语义红色仅用于错误、危险、未读和售罄。

## 3. 仓库与目录边界

本仓库为单仓库多目录结构（2026-09-01 调整，依据课程要求"每组必须建立一个代码仓库"）：各端独立工程、独立进程，通过 RESTful 接口通信，不要求分仓库：

```text
本仓库（单 Git 仓库）/
  frontend/user-h5/        用户端移动 H5（Vue 3 + Vite + Pinia，npm create vue 初始化）
  frontend/merchant-admin/ 商家端桌面后台（React 18 + Vite + Ant Design 5）
  backend/                 Java Spring Boot 后端（含数据库脚本）
  docs/                    课程文档
```

用户端与商家端工程初始化后，目录边界以 `docs/project/项目目录索引.md` 为准；文档与临时产物的跟踪边界如下：

| 路径                                                                                                                                                                                                                               | 规则                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `docs/PRD.md`、`docs/README.md`、`docs/design/**`、`docs/SRS.md`、`docs/project/**`、`docs/frontend/**`、`docs/backend/**`、`docs/testing/**`、`docs/record/**`、`docs/prd-assets/**` | 核心协作、契约和展示文档，纳入 Git 跟踪，方便老师查看过程；PRD 是唯一需求来源，图片为 PRD 必要附件 |
| `test-results/**`、`tmp/**`、`dist/**`                                                                                                                                                                                       | 临时验证和构建产物，不提交                                                                         |

## 4. 展示同学发现前端问题的流程

展示同学发现问题时，优先提交问题单，不直接改主分支。

**提交位置（2026-09-08 修订，负责人拍板）**：正式落盘到 Git 跟踪目录，群聊只作通知。

- 正式落盘：问题记录 / 问题单落 `docs/testing/问题记录/YYYY-MM-DD-<主题>.md`，由测试联调同学收录并登记到 `docs/testing/缺陷跟踪表.md`（编号 `BUG-YYYYMMDD-NNN` / `SHOW-QA-NNN`）；规则见 `docs/project/项目规则.md` §1.1。
- 通知：同时在群聊或共享文档 @ 组长与测试联调同学，只作提醒，不作证据。
- 紧急问题（主链路阻塞、白屏）可先口头或群聊通报，但当天必须补落盘；**不得只发群聊、共享文档、`docs/_archive/**`（已 gitignore）或个人目录**。
- 需要改代码时仍走特性分支 + PR（见 §5）。

问题单格式（落盘文件按此字段书写）：

```text
编号：SHOW-QA-001
页面：
路由：
视口：
操作步骤：
实际结果：
期望结果：
截图或录屏：
严重程度：必须修 / 可后置 / 仅建议
备注：
```

严重程度判断：

| 严重程度 | 判断标准                                                          | 处理方式                       |
| -------- | ----------------------------------------------------------------- | ------------------------------ |
| 必须修   | 主链路无法演示、白屏、按钮无反馈、金额/状态明显错误、文案口径错误 | 组长优先修复             |
| 可后置   | 不影响主链路，但影响观感或说明清晰度                              | 统一收尾修复                   |
| 仅建议   | 展示措辞、截图角度、报告表达优化                                  | 展示组自行整理，必要时同步前端 |

## 5. 展示同学改代码的流程

如果展示同学确实要改代码，必须走分支和 PR：

1. 从最新主分支拉代码。
2. 新建分支，例如 `fix/show-qa-login-text`。
3. 只修改问题相关文件，不顺手重构。
4. 本地运行 `npm run build`。
5. 提交中文 commit。
6. 发给组长 review。
7. 组长确认无冲突、无旧口径、无目录越界后合并。

常用命令模板：

```powershell
git status --short
git pull
git switch -c fix/show-qa-login-text
npm run build
git add 相关文件
git commit -m "fix: 修复展示发现的登录文案问题" -m "- 修正文案" -m "- 验证构建通过"
```

如果已经配置远程仓库，再执行：

```powershell
git push -u origin fix/show-qa-login-text
```

然后在远程仓库页面创建 PR，指定组长 review。当前仓库如果没有远程地址，则先不要强行推送；把分支名、commit 号、修改说明和截图发给组长，由负责人决定如何合并。

提交信息格式：

```text
fix: 修复展示脚本发现的登录文案问题

- 修正登录页商家入口说明
- 验证用户登录和商家登录入口仍可跳转
- 未修改接口
```

展示同学不得直接合并主分支；不熟悉代码时只交问题单和截图。

## 6. 后端同学开发流程

后端同学在本仓库 `backend/` 目录创建 Java 工程，不在前端工程目录内创建。后端工程以独立进程运行，前端通过环境变量连接；接口契约和架构设计在开发前完成最小可开发版本，后续变更须同步记录。

后端启动后，前端联调命令：

```powershell
$env:VITE_API_MODE = "real"
$env:VITE_API_BASE_URL = "http://127.0.0.1:8080/api/v1"
$env:VITE_MOCK_FALLBACK = "false"
npm run dev -- --host 127.0.0.1
```

接口对外统一使用当前契约中的业务编号；数据库内部是否使用数字主键由后端自行决定，不能改变接口路径和字段口径。

后端同学每完成一个模块，需要提供：

- 接口路径。
- 请求参数。
- 返回示例。
- 异常示例。
- 数据库表和种子数据说明。
- 自测截图或 Postman/Apifox 记录。
- 已经和前端联调通过的页面路径。

## 7. 合并前检查

任何代码 PR 合并前必须检查：

```powershell
npm run build
git status --short
```

所有 PR 通用检查（2026-09-05 新增）：

- 检查变更文件中是否携带 `docs/record/daily/**`（`git diff --name-only origin/main...HEAD` 核对）；携带即打回，作者把记录改放 `docs/record/raw/YYYY-MM-DD/` 片段后再提交（规则见 `docs/project/项目规则.md` §2）。
- 检查 TDD 红绿真实性（2026-09-06 新增）：`test:` 提交仅含测试代码与脚手架，diff 中不得出现业务实现文件；在 `test:` 提交上复跑对应测试必须失败（红）、`feat:` 提交后转绿（复跑方式：`git checkout <test提交哈希>` 后按工程跑测试命令，PR #9 打回即为本项命中）；PR 描述或 raw/ 片段应附红绿两端证据（红 X failed / 绿 Y passed），缺失或复跑不红即打回（规则见 `docs/project/TDD实施规划.md` §2.2/§3.1）。

**合并前必跑矩阵（R1，2026-09-10 新增）**：按改动面逐项跑，结果写进 PR 描述（模板见 `.github/pull_request_template.md`），未跑项必须写明理由：

| 改动面 | 必跑命令 | 通过标准 |
| --- | --- | --- |
| 用户端前端（`frontend/user-h5/`） | `npm run build` + `npx vitest run` | 构建退出码 0；测试全绿 |
| 商家端前端（`frontend/merchant-admin/`） | `npm run build` + `npm test` | 同上（`build` 含 `tsc` 类型检查，**只跑 test 不算通过**） |
| 后端（`backend/`） | `mvn -B -DskipTests package`；具备测试库时补 `mvn test` | 构建成功；有库时测试全绿 |
| 文档（`docs/**`） | 口径 grep 复查（列出命令与残留） | 无两套口径、无旧口径残留 |
| 部署脚本 / 配置（`deploy/**`、`.github/**`） | 语法检查（`python -m py_compile`、`bash -n`）+ 必要时干跑 | 无语法错误 |

> 该矩阵来自 2026-09-10 实测教训：合并商家端基线时只跑了 `npm test`，`npm run build` 的 `tsc` 类型错误直到服务器构建才暴露。

**自动化检查（R5/R6，2026-09-10 新增）**：PR 会自动运行 `.github/workflows/ci.yml` 的三端构建与单测，以及 `.github/scripts/commit-hygiene.sh` 的提交规范检查（提交标题格式、正文无序列表、`记录:`/`AI协作:` 尾注、`test:` 提交纯度、是否携带 `docs/record/daily/**`）。CI 红则不得合并；本地跑同一脚本的命令：

```bash
bash .github/scripts/commit-hygiene.sh origin/main
```

`backend-test` 任务（MySQL 服务容器 + 建表种子 + `mvn test`）已于 2026-09-10 首次运行即通过（23 条后端测试），**已提升为必需检查**——本机没有 MySQL 也能通过 CI 得到后端测试结论。

如果修改了接口适配：

- 检查接口路径集中表是否仍是唯一的接口路径来源。
- 检查页面层是否没有直接拼接后端路径。
- 检查 Mock 模式和真实接口模式都能启动。
- 检查 `docs/backend/后端接口契约.md` 是否需要同步。

## 8. 演示前冻结规则

正式演示前建议设置功能冻结点：

- 冻结后不再新增功能。
- 只修 P0 主链路问题、白屏、明显错误文案和展示阻塞问题。
- 展示同学只按最终版本截图，不再使用旧截图。
- 后端未完成的 P1/P2 接口继续使用 Mock 回退，不阻塞演示。
- 演示前最后一次统一运行构建和主链路手测。

## 9. 交付检查

组长交付前确认：

- `git status --short` 干净或只剩明确忽略的临时文件。
- `docs/PRD.md` 与当前实现口径一致。
- 演示脚本不再出现与当前商家端可演示状态冲突的旧口径。
- 后端同学已拿到 `docs/backend/后端接口契约.md` 和 `docs/backend/后端任务分配与联调清单.md`。
- 展示同学已拿到演示脚本与报告素材清单。
