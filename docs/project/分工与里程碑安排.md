## 3. Git 协作纪律

- 每人用自己的账号提交，禁止代提交、禁止最后一天整包上传。
- TDD 证据靠提交顺序体现：同一功能的测试类先提交（允许红），实现后提交（绿），不事后补测试提交。
- 提交信息中文，类型前缀用英文：`feat:` `fix:` `test:` `docs:` `chore:`。
- 代码改动走分支 + PR；用户端 PR 由组长 review，商家端 PR 由组长（付赞平）review，后端 PR 由后端 A review。
- 每天在 `docs/record/daily/YYYY-MM-DD.md` 追加一行（记录规则见 `docs/project/项目规则.md`）；每 2-3 天一次短会对齐，中期验收（第一阶段验收，9/8）前和冻结前各开一次正式对齐。
