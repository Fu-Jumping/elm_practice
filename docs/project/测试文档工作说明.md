## 使用方式

9/4 先从接口级用例和 TDD 矩阵挑选本批失败测试，提交 `test:` 并把首次失败输出记入当天记录；开发完成后再提交实现。接口实际联调时逐条填写请求、响应、数据库核对、页面证据和缺陷编号。发现问题立即登记缺陷表，修复后先补回归测试，再按 `test:` → `fix:` 顺序提交并回归。

当前后端、用户端和接口联调尚未在本次文档工作中执行，因此文档中的执行结果保持“待执行”，没有虚构通过结论。店铺关闭、起送条件等契约尚未由 SRS 固化的状态码，暂按“请求被拒绝且无脏数据”验收，SRS 定稿后再回填精确状态码。
