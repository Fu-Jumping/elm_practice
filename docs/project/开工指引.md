# 开工指引（拿到仓库后的一页速查）

日期：2026-09-02。本页是开工第一天的速查清单，只回答四个问题：环境装什么、先读什么、当天任务去哪查、干完怎么留痕；细节一律以 `docs/README.md` 各角色阅读路径与对应文档为准。

## 1. 全员通用

1. 装环境：Git、Node 18+、JDK 17+、Maven、MySQL（前端同学装前两项即可，后端同学按需装后三项，具体版本以后端架构设计定稿为准）。
2. clone 仓库后，先按 `docs/README.md` 的角色路径读文档；`docs/PRD.md` 是唯一有效 PRD，全组必看。**范围口径（2026-09-09 第二阶段范围决议）**：除平台管理员外全部 P1/P2 本期实施（用户端扩展服务 13 页、商家端扩展经营与消息 7 页），平台管理员已砍掉、不制作页面/接口/数据/测试。
3. 每天开工先 `git pull`；仓库在 `main` 上协作，改代码必须走特性分支 + PR，流程见 `docs/project/小组协作与提交流程.md`。
4. 提交信息用中文、类型前缀用英文（`feat:` `fix:` `test:` `docs:` `chore:`）；TDD 要求同一功能的 `test:`（红）提交早于 `feat:`（绿）提交。
5. 干完活留痕：往 `docs/record/raw/YYYY-MM-DD/` 丢工作片段，或在提交信息末尾带"记录: <一句话>"；规则唯一口径见 `docs/project/项目规则.md`。
6. 当天任务去哪查：日常动作对照 `docs/project/TDD实施规划.md` 第 8 章逐日挂钩表；谁交什么对照 `docs/project/分工与里程碑安排.md`；目录职责对照 `docs/project/项目目录索引.md`。
7. 发现缺陷、阻塞或做出容易遗忘的规避决策：正式条目落 `docs/testing/问题记录/YYYY-MM-DD-<主题>.md` 并登记 `docs/testing/缺陷跟踪表.md`（测试联调同学维护），同时以 raw/ 片段留痕（`docs/record/raw/YYYY-MM-DD/`）随次晨汇总进入当日记录；规则见 `docs/project/项目规则.md` §1.1。
