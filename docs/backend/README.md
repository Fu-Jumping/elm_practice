## 2. 接口契约怎么接手（后端 A：王嘉悦）

- **组长保留区**：第 1 章接口总规则，以及第 3–6 章各接口的"方法/路径/说明"表（资源清单）。
- **后端 A 负责区**：每个接口的请求/响应字段明细、错误码明细、种子数据扩充，以及商家订单接口（契约第 5 章）的优先级归属与设计定夺。对现有草案逐节**确认、修订、扩充**，以自己的 Git 提交落痕，由组长评审定稿。
- **写作纪律**：PRD 已写死的规则（如优惠计算顺序 PRD 7.4、订单状态表 PRD 7.6）只引用章节号，不复述；发现 PRD 未定义或两处冲突，报小组修订，不得自行拍板写入。
- **弱化口径**：契约头部已声明"以实现为准"——后端认为草案细节过严或有误的，直接改并回写即可，不需要事先逐条请示。

## 3. 架构设计怎么写（后端 A：王嘉悦，9/3 前出可开发版本）

创建 `docs/backend/架构设计.md`，至少包含：

- 模块划分：Controller/Service/DAO 分层与各模块职责（账号、店铺、商品、地址、购物车、订单）。
- 数据流：一次下单请求从 Controller 到数据库的完整路径。
- ER 图与实体方案：表结构、主外键、唯一约束；固定演示数据引用契约第 2 章。落点由后端 A、后端 B 商定（写进架构设计或独立数据库文档均可，不重复做两份）。
- 数据库选型与框架版本：Spring Boot/MyBatis 精确版本由后端确认并写明（PRD 待确认项）。
- 端间边界：接口细节一律引用契约章节号，不重复契约内容。
