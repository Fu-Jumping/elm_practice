## 1. 接口总规则

> 本章全部规则为**默认约定**：后端可按实现调整，调整后回写本文即可，前端跟随实现适配。

### 1.1 地址和请求

- 本地服务地址：`http://127.0.0.1:4000`（2026-09-10 统一为 4000，见 BUG-20260908-007）。
- 所有接口路径以 `/api/v1` 开头，例如 `GET /api/v1/stores`。
- 查询条件使用 URL 查询参数；新增和修改使用 JSON 请求体；删除通常不需要请求体。
- 请求和响应统一使用 UTF-8；JSON 接口的 `Content-Type` 为 `application/json`。
- 允许当前前端开发地址跨域访问，例如 `http://127.0.0.1:5173`、`http://localhost:5173` 和 Vite 顺延端口（端口仅为参考，以后端实际放行的开发地址为准）。
- 需要登录的接口从服务端 Session 读取当前用户或商家身份，不接受前端传入的 `userId`、`merchantId` 作为权限依据。

### 1.2 会话

- 登录成功后通过 `Set-Cookie` 写入服务端 Session Cookie；前端请求携带 `credentials`。
- 用户会话和商家会话必须区分角色；用户不能访问商家管理接口，商家不能访问用户的私人地址和订单。
- 未登录返回 `401`；登录成功但角色不匹配返回 `403`。
- 退出登录销毁当前 Session；Session 失效后所有受保护请求都返回 `401`。

### 1.3 统一响应

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

约定：

- HTTP 状态码表达请求结果，`code=0` 表示业务成功；业务失败使用非零 `code`。
- 列表成功返回数组；没有数据返回空数组，不把空列表当作错误。**分页接口（§3.6 搜索）是列表约定的唯一例外**：请求与响应统一使用 `page`/`size`，响应对象含 `list`、`page`、`size`、`total`，`list` 为空数组表示无数据。
- 金额使用数字，单位为元，后端计算后保留两位小数；前端传入的期望金额只用于提示或一致性检查。
- 时间统一使用 `yyyy-MM-dd HH:mm:ss`（东八区），全项目唯一格式；SRS 与本契约一致。
- 布尔值使用 `true/false`；数量、库存使用非负整数。

错误响应：

```json
{
  "code": 40001,
  "message": "商品库存不足",
  "data": null,
  "details": {
    "field": "quantity",
    "reason": "库存最多为 2"
  }
}
```

错误状态最小集合：

| HTTP 状态 | 使用场景 |
| --- | --- |
| `400` | JSON 格式错误、必填字段缺失、字段格式或范围不合法 |
| `401` | 未登录、Session 失效 |
| `403` | 角色不匹配、无权访问资源 |
| `404` | 资源不存在，或资源不属于当前身份时按安全需要统一返回不存在 |
| `409` | 重复注册、状态冲突、库存/金额/版本已变化 |
| `500` | 未预期的服务端错误 |

服务端错误也必须返回 JSON，不能返回服务器默认 HTML 错误页。错误消息应能帮助页面显示可理解的处理建议，但不能泄露密码、数据库细节或堆栈信息。

## 3. P0 用户端接口

### 3.1 用户注册、登录和当前用户

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/users` | 注册用户 |
| `POST` | `/api/v1/auth/login` | 用户登录；请求体中的 `role` 为 `user` |
| `POST` | `/api/v1/auth/logout` | 注销当前会话 |
| `GET` | `/api/v1/me` | 查询当前用户 |
| `PATCH` | `/api/v1/me` | 修改当前用户允许修改的资料 |

注册请求示例：

```json
{
  "account": "13800000002",
  "password": "123456",
  "nickname": "张同学"
}
```

登录请求示例：

```json
{
  "account": "13800000001",
  "password": "123456",
  "role": "user"
}
```

登录成功返回当前用户摘要并建立 Session。账号重复返回 `409`；账号或密码错误返回 `401`；字段不合法返回 `400`。密码不能在响应或日志中返回。

### 3.2 店铺和商品查询

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/stores` | 查询可展示的店铺列表 |
| `GET` | `/api/v1/stores/{storeId}` | 查询店铺详情和营业状态 |
| `GET` | `/api/v1/stores/{storeId}/categories` | 查询店铺分类 |
| `GET` | `/api/v1/stores/{storeId}/products` | 查询店铺商品 |
| `GET` | `/api/v1/products/{productId}` | 查询商品详情 |

`GET /stores` 的可选参数：`keyword`、`categoryId`、`sort`。`sort` 最小取值为 `综合`、`销量`、`距离`，默认 `综合`。列表没有结果返回 `data: []`。

店铺对象至少包含：`storeId`、`name`、`description`、`image`、`rating`、`monthlySales`、`deliveryMinutes`、`startPrice`、`deliveryFee`、`status`。`status` 取 `OPEN`、`CLOSED`、`TEMPORARILY_CLOSED`。

商品对象至少包含：`productId`、`storeId`、`categoryId`、`name`、`description`、`image`、`price`、`stock`、`onSale`。下架商品可以由商家接口查询，但用户端商品列表不得展示为可购买状态。

商品对象本期扩展字段（本期实现（待开发））：`memberPrice`（会员价，非会员仍返回但按 `price` 计价；**与会员折扣不叠加**——配置了 `memberPrice` 的商品按会员价计价且不再打折，未配置的商品才应用会员折扣，2026-09-09 定稿，见 §3.5 与 PRD 7.4 第 5 步）、`tags`（标签）、`specOptions`（规格选项，元素含 `priceDelta` 价差）。规格与会员价字段命名已按 2026-09-09 决议定稿为 `specOptions`/`priceDelta`/`cartLineId`；是否内联返回由后端 A 实现后回写本节。

### 3.3 地址

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/me/addresses` | 查询当前用户地址 |
| `POST` | `/api/v1/me/addresses` | 新增地址 |
| `GET` | `/api/v1/me/addresses/{addressId}` | 查询地址详情 |

### 3.4 购物车

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/cart?storeId={storeId}` | 查询当前用户指定店铺购物车 |
| `POST` | `/api/v1/cart/items` | 加入购物车 |
| `PATCH` | `/api/v1/cart/items/{cartLineId}` | 修改购买数量（规格信息属于规格扩展） |
| `DELETE` | `/api/v1/cart/items/{cartLineId}` | 删除购物车行 |

加入购物车请求示例（基础 P0）：

```json
{
  "storeId": "m002",
  "productId": "p101",
  "quantity": 2
}
```

基础 P0 购物车行的唯一范围是“当前用户 + 店铺 + 商品”，同一商品重复加购合并数量。规格与加料字段按 2026-09-09 决议**本期启用（待开发）**，字段命名定稿为 `specOptions`（规格选项）、`priceDelta`（规格价差）与 `cartLineId`（购物车行编号，见 §4.2）；启用后购物车行唯一范围扩展为“**用户 + 店铺 + 商品 + 规格组合**”，同一商品不同规格不能错误合并（`cartLineId` 区分规格行）。后端重新读取商品价格和上下架状态；客户端提交的单价只能作为显示或一致性提示，不能作为计价依据。数量必须大于 0，数量为 0 的修改由前端改为删除请求或由后端返回明确错误。

### 3.5 订单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/orders` | 从当前用户购物车创建订单 |
| `GET` | `/api/v1/orders` | 查询当前用户订单列表 |
| `GET` | `/api/v1/orders/{orderId}` | 查询当前用户订单详情 |
| `GET` | `/api/v1/orders/{orderId}/items` | 查询订单明细；也可以直接包含在详情中 |
| `POST` | `/api/v1/orders/{orderId}/payment` | P1 模拟支付结果更新 |
| `POST` | `/api/v1/orders/{orderId}/cancel` | 用户取消订单（本期实现（待开发）） |

创建订单请求示例：

```json
{
  "storeId": "m002",
  "addressId": "da001",
  "remark": "少放辣",
  "expectedTotal": 68.00
}
```

创建订单时后端以当前用户购物车和数据库商品数据为主，重新检查店铺营业状态、商品上下架、数量、库存、起送条件和金额；库存校验与扣减在创建订单事务内完成，并发条件更新与 409 保护已按 2026-09-09 决议纳入本期。优惠接入计价后，本段金额规则按本节“优惠计价接入下单”与 PRD 7.4 顺序扩展；打包费与配送费口径见 §10.4 第 1 条（已确认）。金额由后端计价，最终公式（2026-09-09 定稿）：`实付 = 商品小计 − 满减 − 新客立减 − 红包 − 会员折扣 + 配送费（默认 ¥3.00，店铺可配、未配置按 0） − 配送费优惠 + 打包费（¥2.00）`，且**不小于 0**；前端传入金额只用于提示或一致性检查。订单必须保存商品快照、地址快照、金额快照和创建时间；金额快照至少包含商品小计（`itemSubtotal`）、`packagingFee`（打包费）、**`deliveryFee`（配送费，本期新增快照字段）**与实付金额（`total`）。用户端确认订单页与订单详情金额明细为「**基础四行 + 优惠项按实际发生展示**」（2026-09-11 定稿，CHG-004）：基础四行恒为商品小计 / 打包费 / 配送费 / 实付金额；满减、红包、新客立减、会员折扣、配送费优惠等优惠项金额非 0 时各占一行并以品牌橙负数展示，未发生不显示该行，取代原「固定四行」表述。订单头、订单明细以及需要同步的购物车变化必须在一个事务中完成，事务提交成功后清空该用户在该店铺的购物车行，事务失败时购物车保持原状。

订单使用单一状态字段（`merchantStatus` 已废弃）。模拟支付与商家订单推进均已按 2026-09-09 决议纳入本期，状态取值如下：

| 状态 | 含义 | 触发 | 用户端展示 |
| --- | --- | --- | --- |
| `PENDING_PAYMENT` | 待支付 | 创建订单成功 | 待支付（15 分钟倒计时） |
| `PROCESSING` | P0 阶段状态（进行中，**仅 P0 保留，不再作为支付后状态**） | P0 阶段创建订单后的历史口径 | 进行中（仅 P0 阶段） |
| `PENDING` | 待接单 | **支付成功即进入此状态（2026-09-09 定稿）** | 待接单 |
| `COOKING` | 制作中 | 商家接单 | 制作中 |
| `DELIVERING` | 配送中 | 商家出餐配送 | 配送中 |
| `COMPLETED` | 已完成 | 商家完成订单 | 已完成；未评价时展示“待评价” |
| `CANCELLED` | 已取消 | 用户取消（未支付或未接单，本期实现（待开发）） | 已取消 |

- 定稿流转（2026-09-09 负责人拍板，§10.4 第 1 条）：`PENDING_PAYMENT` →（支付成功）→ `PENDING`（待接单）→（商家接单）→ `COOKING` → `DELIVERING` → `COMPLETED`；用户取消进入 `CANCELLED`（见本节取消规则）。**`PROCESSING` 仅作为 P0 阶段状态保留，不再作为支付后的状态**。当前实现（`OrderMapper.markPaid` 写 `PROCESSING`、`OrderService` 流转 `PROCESSING`→`PENDING`）属偏差，需按本节定稿修正（本期实现（待开发），修正后回写 §9）。前端需补齐 `PENDING`/`COOKING`/`DELIVERING`/`CANCELLED` 文案映射。
- 状态只能按顺序推进；跳过状态（如 `PENDING` 直接到 `COMPLETED`）返回 `409`；同一目标状态重复提交幂等返回当前订单，不重复扣减库存或跨越下一状态。
- 订单列表支持 `status` 查询参数，默认按创建时间倒序；取值 `PENDING_PAYMENT`、`PENDING`、`COOKING`、`DELIVERING`、`COMPLETED`、`CANCELLED`；用户端列表筛选取值“全部/待支付/进行中/已完成/待评价/已取消”由后端按状态与评价情况计算（“待评价”不是独立存储状态）。
- 待支付倒计时（本期实现（待开发））：订单响应返回 `payDeadline`（= `createdAt` + 15 分钟），前端据此倒计时；超时后支付返回 `409`，超时不自动回补库存（§7）。
- 再来一单（本期实现（待开发））：不新增接口；用户端按 `GET /api/v1/orders/{orderId}` 明细重新调用 `POST /api/v1/cart/items`，商品下架或库存不足时按 §3.4 规则拒绝并提示。
- 是否已评价（口径补充，2026-09-11）：订单响应新增 `reviewed` 布尔字段（订单创建为 `false`，用户提交评价成功后置 `true`），用于用户端「待评价」文案与去评价入口的判定；「待评价」仍不是独立存储状态，由 `status`（`COMPLETED`）与 `reviewed` 共同计算。

模拟支付不接第三方支付，不传银行卡或支付平台信息。支付接口只能更新当前用户自己的待支付订单；重复支付请求返回当前结果，不重复扣款或生成订单。

**用户取消订单（`POST /api/v1/orders/{orderId}/cancel`，本期实现（待开发））**

请求体：

```json
{
  "reason": "地址填错了"
}
```

规则：

- 只能取消当前用户自己的订单，身份从 Session 读取；订单不属于当前用户按 `404` 处理。
- 仅 `PENDING_PAYMENT`（未支付）与 `PENDING`（已支付未接单；按 2026-09-09 定稿状态机，支付成功即 `PENDING`）允许取消；`COOKING` 及之后返回 `409`，`details` 说明当前状态不可取消。
- `reason` 必填且不能为空白，长度固定为 **1–50 个字符**（2026-09-10 负责人拍板定稿）；缺失、全空白或超长返回 `400`。
- 取消在同一事务内完成：订单状态置 `CANCELLED`，写入 `cancelReason`、`cancelledAt`、`cancelledBy=USER`，并**回补该订单明细对应的商品库存**（含规格行）；订单头、明细快照与金额快照保留，不物理删除。
- 重复取消幂等：订单已是 `CANCELLED` 时返回当前订单（HTTP `200`），不重复回补库存。
- 取消与支付并发时以数据库条件更新（`WHERE status IN (...)`）为准，只有一个请求生效，另一个返回 `409`。
- 不接真实退款与资金处理；已支付订单取消只改状态与库存，不产生退款流水（课程简化口径）。
- 商家端不提供取消接口；商家订单列表与详情展示 `CANCELLED`、`cancelReason` 与 `cancelledAt`（§5.1、§5.2）。

取消成功后的订单响应新增字段：`cancelReason`、`cancelledAt`、`cancelledBy`。

**优惠计价接入下单（已实现，PRD 7.4 七步顺序；第⑥步用户红包随批次⑥接入，当前恒 0）**

- `promotions` 配置（§6.3）本期起真正影响下单计价；金额一律以后端计算为准，前端 `expectedTotal` 只用于提示与一致性检查。
- 计算顺序按 PRD 7.4：① 商品小计（单价含规格价差；会员购买时配置了 `memberPrice` 的商品按会员价计价、不再应用会员折扣，未配置的才打折）→ ② 店铺满减（取最大满足的阶梯）→ ③ 新客立减（店铺新用户首单）→ ④ 配送费与配送费优惠（只作用于配送费）→ ⑤ 会员折扣（作用于商品小计）→ ⑥ 用户红包（满足门槛与适用范围，一单一红包）→ ⑦ 最终金额且不小于 0。
- 演示数值：满 20 减 2、满 40 减 5、新客立减 3 元、免配送费门槛 30 元、会员 95 折、红包门槛与适用范围由种子数据定义。
- 金额快照字段（2026-09-09 定稿命名，§10.4 第 1、2 条）：`itemSubtotal`、`packagingFee`、`deliveryFee`、`fullReductionAmount`、`newCustomerAmount`、`memberDiscountAmount`、`couponAmount`、`deliveryFeeDiscount`、`total`；其中 `deliveryFee` 为本期新增快照字段。
- 定稿公式与明细行数（2026-09-09 定稿，PRD 7.4 第 7 步）：`实付 = 商品小计 − 满减 − 新客立减 − 红包 − 会员折扣 + 配送费（默认 ¥3.00，店铺可配、未配置按 0） − 配送费优惠 + 打包费（¥2.00）`，且不小于 0；**打包费与配送费同时进入实付金额**，确认订单页、订单详情与支付页的金额明细口径为「**基础四行 + 优惠项按实际发生展示**」（基础四行 / 优惠项按实际发生展示，2026-09-11 定稿，CHG-004）：基础四行为商品小计 / 打包费 / 配送费（为 0 仍显示 ¥0.00）/ 实付金额；满减优惠、红包优惠、新客立减、会员折扣、配送费优惠在金额非 0 时各占一行并以品牌橙负数展示，未发生不显示该行。
- 非法优惠配置或超额优惠必须被拒绝或限制到合法范围（负数、折扣率越界、过期红包等），不得出现负金额。

| 方法 | 路径 | 说明 |

### 5.2 商家订单状态推进（P1，扩展：商家接单与订单状态推进）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `PATCH` | `/api/v1/merchant/orders/{orderId}/status` | 推进订单状态（P1 扩展） |

商家订单状态最小取值：`PENDING`、`COOKING`、`DELIVERING`、`COMPLETED`，以及只读展示的 `CANCELLED`。合法顺序为待接单→制作中→配送中→已完成；”配送中”只是课程演示状态，不建设骑手、地图和实时配送系统。状态推进必须检查当前状态、订单归属并支持重复请求幂等；订单已被其他操作修改时返回 `409`，页面提示刷新。

取消与订单状态相关口径（本期实现（待开发），与 §3.5、PRD 7.6 一致）：

- 商家端**不提供取消订单接口**；用户取消后商家端订单列表与详情展示 `CANCELLED`、`cancelReason` 与 `cancelledAt`，已取消订单不可再推进到任何后续状态（尝试推进返回 `409`）。
- 商家订单列表 `status` 筛选支持 `CANCELLED`；已取消订单不计入经营数据（§6.3 只统计有效订单）。
- 商家推进订单状态到 `DELIVERING`（配送中）时只更新订单状态；配送进度由订单状态与订单详情时间线表达（§10.2 已砍，CHG-002），不建配送单，订单完成即 `COMPLETED`。

## 7. 事务、并发和幂等

- 订单创建使用数据库事务，订单头、商品明细快照和购物车变化不能出现半成功。
- 库存扩展采用数据库事务和条件更新或行级锁保护，例如仅在 `stock >= quantity` 时扣减；本项目不引入生产者/消费者、消息队列或异步库存服务。
- 同一按钮的重复点击由前端禁用，后端仍必须通过唯一约束、状态条件或幂等键防止重复写入。
- 商品下架、店铺关闭、金额变化、库存不足和订单状态变化都以提交时后端结果为准。
- 用户和商家查询、修改、删除资源前必须检查身份和归属；不能只依赖 URL 中的编号。
- 发生并发冲突返回 `409`，响应说明“数据已变化，请刷新后重试”，页面重新读取相关数据。

库存回补与不回补口径（2026-09-09 决议统一，本期实现（待开发））：

- **用户取消订单**：在取消事务内回补库存（按订单明细的规格行逐条加回），与状态置 `CANCELLED` 同事务提交；重复取消不重复回补；回补以条件更新 `WHERE status IN ('PENDING_PAYMENT','PENDING')` 保证并发下只生效一次。
- **支付**：不重复扣库存，也不回补库存；库存只在订单创建事务内扣减一次（PRD 7.16）。
- **支付超时未支付**：不自动回补库存（课程简化口径），与用户取消的回补规则不得混用；两种口径必须由测试用例分别覆盖。
- **红包占用**：下单使用红包与订单写入同事务，红包以条件更新（`used=false` 且未过期）锁定，并发下同一红包只允许一个订单使用成功。
- **配送状态**：配送单与配送单推进口径随 CHG-002 一并作废；配送进度改由订单状态（`DELIVERING`=配送中）表达，不建配送单、不参与库存回补。

## 9. 后端 A 实现补充（2026-09-06）

当前 Spring Boot 实现统一返回 `ApiResponse`：成功固定为 `code=0`、`message=success`；错误响应保留 `data=null`，并按需要提供 `details`。实现使用以下业务错误码，HTTP 状态仍是客户端判断请求结果的首要依据：

| code | HTTP | 场景 |
| --- | --- | --- |
| `40001` | 400 | 请求体、必填字段、格式或数值范围不合法 |

| `40901` | 409 | 重复注册、库存/状态/金额冲突 |

- **不接对象存储**：不使用 OSS、CDN 或云存储，文件保存到后端本地目录 `backend/uploads/`（配置项 `file.upload-dir` 默认 `backend/uploads/`），读取经静态映射 `/uploads/**` 提供（2026-09-09 定稿，§10.4 第 3 条）；上传目录**不入 Git**（写入 `.gitignore`，目录内保留 `.gitkeep`）。
- 响应返回 `url`、`fileName`、`size`、`contentType`；业务接口只保存 `url` 引用，上传接口本身不写业务表。
- 限制（2026-09-09 定稿）：类型仅 `image/jpeg`、`image/png`、`image/webp`（即 jpg/jpeg/png/webp）；单张 ≤ 2MB；一次只上传一张（多图由前端多次调用）；**数量上限为商品图 1 张、评价图最多 3 张**；文件名由后端生成，不使用用户原始文件名（防路径穿越）。
- 权限（2026-09-09 定稿）：商家端商品图片需商家身份且**只能上传本店商品图**，用户端评价图片需用户身份且**只能上传自己订单评价的图**；未登录 `401`，角色不符或越权访问非本店/非本人资源返回 `403`。
- 失败重试：类型或大小不合法返回 `400`（`details` 说明限制），写盘失败返回 `500`；前端上传失败保留本地预览并允许重试，上传成功后才把 `url` 提交给商品表单或评价接口。
- 数量与大小上限已按 2026-09-09 决议定稿（商品图 1 张、评价图最多 3 张、单张 ≤ 2MB、类型 jpg/jpeg/png/webp、目录 `backend/uploads/` + 静态映射 `/uploads/**`）；如老师阶段 2 变更另有规定，以变更发布后重新拍板为准。

### 10.2 简化配送 **（2026-09-11 已砍掉，CHG-002）** — **本节以下全部接口、对象字段与规则均已作废、不实现**，仅作为设计过程留存

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/orders/{orderId}/delivery` | 用户端只读查询配送单 |
| `GET` | `/api/v1/merchant/orders/{orderId}/delivery` | 商家端查询配送单 |
| `PATCH` | `/api/v1/merchant/orders/{orderId}/delivery/status` | 商家端推进配送状态 |

配送单对象：`deliveryId`、`orderId`、`status`、`receiverName`、`receiverPhone`、`addressSnapshot`、`courierName`（课程演示占位，可为空）、`createdAt`、`updatedAt`。
