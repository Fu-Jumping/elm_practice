# 演示目录对齐报告（2026-09-08）

## 结论

服务器旧库已经完成一次目录对齐。用户端真实接口、商家端真实接口和前端 mock 现在使用同一套店铺、分类、商品编号与图片文件；旧商品行和旧购物车行已清理，历史订单仍保留自己的商品快照。

## 已定位的问题

旧 seed 与 `图片清单.md` 有两套互相冲突的口径：

- `p101` 旧值是“吮指原味鸡”，却指向 `product-m002-06.jpg`；前端 mock 是“香辣鸡腿堡”并指向 `product-m002-01.jpg`。
- m002 的数据库只有一个“热销推荐”分类，前端却按“主食 / 小食 / 饮品”展示，商品分类 ID 因此全部错位。
- m001、m003、m004、m005 的数据库商品仍是旧编号（p111/p131/p141/p151 等），与图片清单中的 p201–p209 和前端菜单不一致。
- `TEMPORARILY_CLOSED` 在用户端只按 `CLOSED` 判断，老胖烧烤真实接口会显示为临时闭店却仍可加购。

## 修复口径

- 以 `图片清单.md` 作为素材真源；主菜单统一为 p101–p106，其余店铺统一为 p201–p209。
- m002 分类为 c101 主食、c102 小食、c103 饮品；其它店铺使用按店铺分段的分类 ID，避免跨店复用。
- seed 与资源 seed 同步；已有服务器通过 `backend/database/seed/catalog-alignment.sql` 做幂等迁移，不重置用户、订单或 QA 临时店铺。
- 订单明细继续使用快照，演示订单 o1001–o1003 的名称、图片、分类、单价和合计同步到新目录。
