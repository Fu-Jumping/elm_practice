# 后端架构设计

版本：v1.1（2026-09-07，MyBatis + MySQL 持久化接入）

## 1. 技术选型与边界

后端采用 Java 17、Spring Boot 3.5.5、Spring MVC、Jakarta Servlet Session 和 MyBatis 3.0.4。持久化为云服务器 MySQL 8（`82.157.137.114:3306`），连接参数经环境变量注入（`DB_HOST/DB_USER/DB_PASSWORD/DB_NAME`），密码不入仓库；建表与种子 SQL 位于 `backend/database/`，启动由 `DatabaseInitializer` 幂等执行。Controller、Service 和接口契约在内存版基础上保持不变，仅持久化层从 `InMemoryRepository` 替换为 MyBatis Mapper。服务监听 `127.0.0.1:8080`，统一 REST 前缀为 `/api/v1`。跨域仅放行本地用户端和商家端开发地址，并允许 Cookie 凭据。

接口字段、HTTP 状态码和 P0/P1 范围以《后端接口契约》为准，本文件只说明结构和数据流。

## 2. 分层与模块

```text
HTTP + Session
  Controller       解析路径、请求体、查询参数；只负责身份入口和响应包装
  Service          业务规则、归属校验、金额/状态校验、@Transactional 事务边界
  Mapper           MyBatis 注解 SQL；14 个接口对应 14 张表，行锁/条件更新下推 SQL
  Domain           用户、商家、店铺、分类、商品、地址、购物车、订单及快照
```

模块职责：

- `AuthService`：用户/商家注册、登录、注销和 Session 角色隔离；密码只保存 SHA-256 摘要（`HashUtil`），不进入响应；商家注册（merchant+store+category 多表）同事务。
- `StoreService`：用户端店铺、分类、可售商品查询，以及商家店铺资料更新。
- `CatalogService`：商家分类、商品增删改、上下架和库存校验。
- `AddressService`：当前用户地址 CRUD、唯一默认地址和删除默认地址后的回退选择。
- `CartService`：当前用户/店铺/商品范围的购物车合并、数量与商品状态校验；加购/改数量用 `findByIdForUpdate` 行锁读商品。
- `OrderService`：下单计价、商品/地址快照、库存扣减（`decreaseStock` 带 `WHERE stock>=?` 条件）、购物车清理、用户与商家订单查询，以及 P1 支付和状态推进；`create` 为 `@Transactional`，任一步骤失败整体回滚。
- `ExtensionService`：评价、会话、消息、店铺促销、商家概览（营收口径只算已支付订单）。
- `IdGenerator`：基于 `id_sequence` 表的 `SELECT ... FOR UPDATE` + `UPDATE` 生成全局唯一 ID，替代原 `AtomicLong`。
- `GlobalExceptionHandler`：将校验、权限、资源不存在、冲突和未预期异常统一转换为 JSON 响应；未预期异常打 ERROR 日志。

## 3. 下单与支付数据流

1. `POST /api/v1/orders` 由 `OrderController` 从 Session 取得用户身份，拒绝请求体中的伪造用户编号。
2. `OrderService` 校验店铺营业状态、地址归属和该用户/店铺购物车。
3. 在同步事务区内重新读取商品价格、上下架和库存，计算商品小计、固定打包费 2.00 元和实付金额。
4. 先构造商品快照和地址快照，再写入订单头/明细；任一商品校验失败即抛出异常，不执行后续库存与购物车变化。
5. 成功后扣减库存、增加销量并清空该用户该店购物车，订单状态固定初始化为 `PENDING_PAYMENT`（模拟支付扩展已选定）；幂等键命中时直接返回原订单。
6. `POST /api/v1/orders/{orderId}/payment` 仅作用于当前用户的待支付订单：15 分钟内支付成功进入 `PROCESSING` 并记录 `paidAt`，超时返回 409 且不回补库存；支付完成前商家端订单查询按不存在处理。
7. Controller 使用统一 `ApiResponse` 返回订单对象；详情包含 `itemSubtotal`、`packagingFee`、`total`、`paidAt`、地址和明细。

当前 `OrderService.create` 标注 `@Transactional`，购物车行 `FOR UPDATE` 串行化、库存 `decreaseStock` 带 `WHERE stock >= ?` 条件兜底并发，幂等由 `(user_id, idempotency_key)` 唯一约束兜底；任一步骤失败整体回滚。

## 4. 实体与约束

| 实体 | 关键字段 | 约束 |
| --- | --- | --- |
| users | user_id、account、password_hash | account 唯一 |
| merchants | merchant_id、account、store_id | account 唯一，store_id 唯一 |
| stores | store_id、merchant_id、status | status 为 OPEN/CLOSED/TEMPORARILY_CLOSED |
| categories | category_id、store_id、name | `(store_id,name)` 唯一 |
| products | product_id、store_id、category_id、price、stock、on_sale | 价格/库存非负；商品归属店铺 |
| addresses | address_id、user_id、is_default、updated_at | 读写按 user_id 隔离；每用户最多一个默认地址 |
| cart_lines | cart_line_id、user_id、store_id、product_id、quantity | `(user_id,store_id,product_id)` 唯一，数量大于 0 |
| orders | order_id、user_id、store_id、address_snapshot、item_subtotal、packaging_fee、total、status、paid_at、idempotency_key | 订单头与明细同事务；状态按契约状态机；`(user_id, idempotency_key)` 唯一约束兜底幂等 |
| order_items | order_id、product_snapshot、unit_price、quantity | 保存下单时商品快照 |

稳定业务编号直接对外返回；数据库内部自增主键可在 SQL 版本中增加，但不得泄露。

## 5. 统一安全规则

Session 属性 `ELM_AUTH_PRINCIPAL` 保存 `Principal(id, role)`。所有受保护服务先检查角色，再检查资源归属：角色不符返回 403，资源不属于当前用户/店铺按安全策略返回 404。密码、堆栈和数据库细节不写响应或日志。全局异常处理器保证 API 错误不降级为 HTML。

## 6. 运行和持久化配置

```powershell
cd backend
$env:JAVA_HOME="<本机 JDK 17 路径>"
$env:DB_HOST="82.157.137.114"; $env:DB_USER="elm"; $env:DB_PASSWORD="<密码>"; $env:DB_NAME="elm_practice"
mvn spring-boot:run
```

连接参数经环境变量注入（`DB_HOST/DB_USER/DB_PASSWORD/DB_NAME`），密码不入仓库；`application.properties` 默认指向本机，部署时设置 `DB_*` 覆盖。建表与种子由 `DatabaseInitializer` 启动时幂等执行（users 表为空才插种子，避免重启重置运行期库存/销量）。

测试连独立测试库 `elm_practice_test`，每用例前 `reset.sql` 复位种子：

```powershell
$env:DB_NAME="elm_practice_test"
mvn clean test
```
