# 后端架构设计

版本：v1.2（2026-09-09，第二阶段范围决议同步：新增模块实体与事务口径）

## 1. 技术选型与边界

后端采用 Java 17、Spring Boot 3.5.5、Spring MVC、Jakarta Servlet Session 和 MyBatis 3.0.4。持久化为云服务器 MySQL 8（`82.157.137.114:3306`），连接参数经环境变量注入（`DB_HOST/DB_USER/DB_PASSWORD/DB_NAME`），密码不入仓库；建表与种子 SQL 位于 `backend/database/`，启动由 `DatabaseInitializer` 幂等执行。Controller、Service 和接口契约在内存版基础上保持不变，仅持久化层从 `InMemoryRepository` 替换为 MyBatis Mapper。服务监听 `127.0.0.1:4000`，统一 REST 前缀为 `/api/v1`。跨域仅放行本地用户端和商家端开发地址，并允许 Cookie 凭据。

接口字段、HTTP 状态码和 P0/P1 范围以《后端接口契约》为准，本文件只说明结构和数据流。

## 2. 分层与模块

```text
HTTP + Session
  Controller       解析路径、请求体、查询参数；只负责身份入口和响应包装
  Service          业务规则、归属校验、金额/状态校验、@Transactional 事务边界
  Mapper           MyBatis 注解 SQL；当前 14 张表（users/merchants/stores/categories/products/addresses/cart_lines/orders/order_items/reviews/conversations/messages/promotions/id_sequence），行锁/条件更新下推 SQL
  Domain           用户、商家、店铺、分类、商品、地址、购物车、订单及快照；本期新增优惠、红包、评价扩展、会话、消息、收藏、会员、通知、配送单与规格实体
```

模块职责：

- `AuthService`：用户/商家注册、登录、注销和 Session 角色隔离；密码只保存 SHA-256 摘要（`HashUtil`），不进入响应；商家注册（merchant+store+category 多表）同事务。
- `StoreService`：用户端店铺、分类、可售商品查询，以及商家店铺资料更新。
- `CatalogService`：商家分类、商品增删改、上下架和库存校验。
- `AddressService`：当前用户地址 CRUD、唯一默认地址和删除默认地址后的回退选择。
- `CartService`：当前用户/店铺/商品范围的购物车合并、数量与商品状态校验；加购/改数量用 `findByIdForUpdate` 行锁读商品。
- `OrderService`：下单计价、商品/地址快照、库存扣减（`decreaseStock` 带 `WHERE stock>=?` 条件）、购物车清理、用户与商家订单查询，以及 P1 支付和状态推进；`create` 为 `@Transactional`，任一步骤失败整体回滚。
- `ExtensionService`：评价、会话、消息、店铺促销、商家概览（营收口径只算已支付订单）。
- 本期新增模块（2026-09-09 决议，**本期实现（待开发）**）：订单取消与库存回补归入 `OrderService`；优惠计价归入 `OrderService`（读 `PromotionMapper` + 红包/会员数据）；新增 `FavoriteService`、`CouponService`、`MemberService`、`NotificationService`、`DeliveryService`、`UploadService`（本地目录存储，不接对象存储）、`SpecService`（规格与分类绑定）；`ExtensionService` 扩展评价图片/标签与双端未读，新增 `StatsService` 负责“有效订单”统计口径。具体拆分以后端实现为准，实现后回写本节。
- `IdGenerator`：基于 `id_sequence` 表的 `SELECT ... FOR UPDATE` + `UPDATE` 生成全局唯一 ID，替代原 `AtomicLong`。
- `GlobalExceptionHandler`：将校验、权限、资源不存在、冲突和未预期异常统一转换为 JSON 响应；未预期异常打 ERROR 日志。

## 3. 下单与支付数据流

1. `POST /api/v1/orders` 由 `OrderController` 从 Session 取得用户身份，拒绝请求体中的伪造用户编号。
2. `OrderService` 校验店铺营业状态、地址归属和该用户/店铺购物车。
3. 在同步事务区内重新读取商品价格、上下架和库存，计算商品小计、固定打包费 2.00 元和实付金额。
4. 先构造商品快照和地址快照，再写入订单头/明细；任一商品校验失败即抛出异常，不执行后续库存与购物车变化。
5. 成功后扣减库存、增加销量并清空该用户该店购物车，订单状态固定初始化为 `PENDING_PAYMENT`（模拟支付扩展已选定）；幂等键命中时直接返回原订单。
6. `POST /api/v1/orders/{orderId}/payment` 仅作用于当前用户的待支付订单：15 分钟内支付成功进入 `PROCESSING` 并记录 `paidAt`，超时返回 409 且不回补库存；支付完成前商家端订单查询按不存在处理。
7. Controller 使用统一 `ApiResponse` 返回订单对象；详情包含 `itemSubtotal`、`packagingFee`、`total`、`paidAt`、地址和明细。

当前 `OrderService.create` 标注 `@Transactional`，购物车行 `FOR UPDATE` 串行化、库存 `decreaseStock` 带 `WHERE stock >= ?` 条件兜底并发，幂等由 `(user_id, idempotency_key)` 唯一约束兜底；任一步骤失败整体回滚。

优惠计价（本期实现（待开发））：第 3 步由“商品小计 + 固定打包费”扩展为 PRD 7.4 的七步顺序——① 商品小计（含规格价差、会员按会员价）→ ② 店铺满减（取最大满足阶梯）→ ③ 新客立减（店铺新用户首单）→ ④ 配送费与配送费优惠 → ⑤ 会员折扣（作用于商品小计）→ ⑥ 用户红包（门槛与适用范围校验后锁定）→ ⑦ 最终金额不小于 0；优惠配置读 `promotions` 表，红包与会员数据在本事务内读取并锁定，金额快照新增优惠字段（命名以契约 §3.5/§10.4 定稿为准）。**打包费与配送费同时进入实付金额**（契约 §10.4 第 1、2 条，2026-09-09 负责人拍板定稿，**非待确认项**）；实现按定稿公式执行。

取消订单（本期实现（待开发））：`OrderService.cancel` 为 `@Transactional`——先按 `WHERE order_id=? AND user_id=?` 校验归属，再条件更新 `status IN ('PENDING_PAYMENT','PENDING')` 为 `CANCELLED` 并写入 `cancelReason`、`cancelledAt`、`cancelledBy`；更新成功后按订单明细逐条 `increaseStock` 回补库存（含规格行），任一步失败整体回滚；重复取消不重复回补。**支付不扣减也不回补库存，库存只在创建订单事务内扣减一次**（契约 §7）。

## 4. 实体与约束

| 实体 | 关键字段 | 约束 |
| --- | --- | --- |
| users | user_id、account、password_hash | account 唯一 |
| merchants | merchant_id、account、store_id | account 唯一，store_id 唯一 |
| stores | store_id、merchant_id、status | status 为 OPEN/CLOSED/TEMPORARILY_CLOSED |
| categories | category_id、store_id、name | `(store_id,name)` 唯一 |
| products | product_id、store_id、category_id、price、stock、on_sale | 价格/库存非负；商品归属店铺 |
| addresses | address_id、user_id、is_default、updated_at | 读写按 user_id 隔离；每用户最多一个默认地址 |
| cart_lines | cart_line_id、user_id、store_id、product_id、quantity | `(user_id,store_id,product_id)` 唯一，数量大于 0 |
| orders | order_id、user_id、store_id、address_snapshot、item_subtotal、packaging_fee、total、status、paid_at、idempotency_key | 订单头与明细同事务；状态按契约状态机；`(user_id, idempotency_key)` 唯一约束兜底幂等 |
| order_items | order_id、product_snapshot、unit_price、quantity | 保存下单时商品快照 |
| product_specs | spec_id、product_id、name、price_delta、sort_order | 规格价差非负；随商品归属校验（本期实现（待开发）） |
| promotions | store_id、full_reductions、new_customer_amount、free_delivery_threshold、member_discount_rate、delivery_fee | 每店一份；数值校验非负、折扣率 0–1（本期扩展字段待开发） |
| coupons | coupon_id、user_id、amount、threshold、scope、store_id、valid_from、valid_to、used | 归属用户；门槛/范围/有效期校验；`used` 条件更新保证一单一红包（本期实现（待开发）） |
| members | user_id、member_opened、discount_rate、activated_at | 每用户一条；会员标识来自种子数据或后台标记，不做开通与续费（本期实现（待开发）） |
| reviews | review_id、order_id、user_id、store_id、rating、content、tags、images、reply、replied_at | 一单一评唯一约束；评分 1–5；回复更新原记录（图片与标签本期实现（待开发）） |
| favorites | favorite_id、user_id、store_id、created_at | `(user_id, store_id)` 唯一；按用户隔离（本期实现（待开发）） |
| conversations | conversation_id、order_id、user_id、store_id、unread、merchant_unread | 一单一会话；双端未读分别记录 |
| messages | message_id、conversation_id、sender_role、content、created_at | 内容非空且有长度上限；按会话归属校验 |
| notifications | notification_id、user_id、type、title、content、related_id、is_read、created_at | 归属用户；类型取 ORDER/COUPON/MEMBER（本期实现（待开发）） |
| deliveries | delivery_id、order_id、status、receiver_name、receiver_phone、address_snapshot、created_at、updated_at | 订单一对一；状态 PENDING_DELIVERY/DELIVERING/DELIVERED，条件更新推进（本期实现（待开发）） |
| file_uploads | file_id、owner_id、owner_role、scene、file_name、content_type、size、created_at | 本地目录存储；类型/大小白名单；不使用用户原始文件名（本期实现（待开发）） |

订单取消字段（orders 表扩展，本期实现（待开发））：`cancel_reason`、`cancelled_at`、`cancelled_by`；状态枚举增加 `CANCELLED`。

稳定业务编号直接对外返回；数据库内部自增主键可在 SQL 版本中增加，但不得泄露。

## 5. 统一安全规则

Session 属性 `ELM_AUTH_PRINCIPAL` 保存 `Principal(id, role)`。所有受保护服务先检查角色，再检查资源归属：角色不符返回 403，资源不属于当前用户/店铺按安全策略返回 404。密码、堆栈和数据库细节不写响应或日志。全局异常处理器保证 API 错误不降级为 HTML。

## 6. 运行和持久化配置

```powershell
cd backend
$env:JAVA_HOME="<本机 JDK 17 路径>"
$env:DB_HOST="82.157.137.114"; $env:DB_USER="elm"; $env:DB_PASSWORD="<密码>"; $env:DB_NAME="elm_practice"
mvn spring-boot:run
```

连接参数经环境变量注入（`DB_HOST/DB_USER/DB_PASSWORD/DB_NAME`），密码不入仓库；`application.properties` 默认指向本机，部署时设置 `DB_*` 覆盖。建表与种子由 `DatabaseInitializer` 启动时幂等执行（users 表为空才插种子，避免重启重置运行期库存/销量）。

测试连独立测试库 `elm_practice_test`，每用例前 `reset.sql` 复位种子：

```powershell
$env:DB_NAME="elm_practice_test"
mvn clean test
```

图片上传目录（本期实现（待开发））由配置项 `file.upload-dir` 指定（默认 `backend/upload/images`），不接对象存储；目录不入仓库，部署时创建并保证可写。

## 7. 事务与并发口径（2026-09-09 决议，本期实现（待开发））

| 场景 | 事务与并发口径 |
| --- | --- |
| 创建订单 | 订单头、明细快照、金额快照、库存扣减与购物车清空同一事务；库存 `decreaseStock` 带 `WHERE stock >= ?` 条件；失败整体回滚 |
| 模拟支付 | 只更新支付状态与 `paid_at`；**不扣库存、不回补库存**；重复支付幂等返回当前订单 |
| 支付超时 | 超时后支付返回 409，**不自动回补库存**（课程简化口径），与取消回补规则不得混用 |
| 用户取消 | 同一事务内条件更新状态为 `CANCELLED` 并回补库存；条件更新 `WHERE status IN ('PENDING_PAYMENT','PENDING')` 保证并发下只生效一次；重复取消幂等且不重复回补 |
| 商家状态推进 | 条件更新目标状态（`WHERE status=<当前状态>`）；跳级、重复或并发修改返回 409，重复推进同一状态幂等 |
| 红包使用 | 下单与红包锁定同事务，条件更新 `WHERE used=false AND valid_to>=now`；并发下同一红包只允许一个订单成功 |
| 配送状态推进 | 条件更新 `WHERE status=<当前状态>`；跳级或回退返回 409，重复推进幂等 |
| 图片上传 | 只写文件与上传记录，不参与业务事务；业务接口保存 `url` 引用，上传失败不产生半成品引用 |

订单状态枚举新增 `CANCELLED`；当前实现中支付成功后先进入 `PROCESSING` 过渡态再进入 `PENDING`，与 PRD 7.6 状态表的差异见契约 §10.4 第 1 条，确认后统一并回写本节。
