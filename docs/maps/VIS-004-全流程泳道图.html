段 1 · 登录与下单（P0 主链路，含模拟支付与库存一致性支线）库存检查与模拟支付属本期 P1，以虚线支线标注
① 打开应用、浏览店铺与商品
② 路由守卫检查会话；渲染首页 / 店铺 / 商品GET /stores、GET /stores/{id}
③ 提交登录、加购与地址POST /auth/login · POST /cart/items（同店限制）· GET/POST /addresses
④ 校验账号与角色；建立 Session（Cookie）；校验商品上下架与数量
⑤ 读写账号、店铺、商品、购物车、地址
⑥ users / merchants / stores / products / categories / cart_lines / addresses
⑦ 确认订单页提交下单POST /orders（含 couponId、idempotencyKey）
⑧ 单事务：校验营业状态 / 上下架 / 库存 / 起送 → 七步优惠计价 → 扣库存 → 写订单头 + 明细 + 金额快照 → 清空购物车
⑨ 事务提交（订单头、明细快照、购物车变更同时生效）
⑩ orders / order_items / cart_lines 同事务写入；订单保存商品、地址与金额快照
⑫ 渲染订单：状态「待支付」+ 倒计时；跳转支付页
⑪ 返回订单（PENDING_PAYMENT + payDeadline，金额以后端计价为准）
⑭ 支付页倒计时结束前「立即支付」POST /orders/{orderId}/payment（本期 P1）
⑮ 置「待接单」并写订单通知；库存只在⑧扣减一次，支付不重复扣减也不回补
P0 必画异常分支（虚线）未登录 / 越权、价格变化、事务失败、重复请求
未登录访问受保护接口返回 401；访问非本人订单 / 非本店资源返回 403（前端按守卫跳登录）
前端按 401 引导登录；按 403 提示无权访问
价格变化：后端按当前商品价与优惠配置重新计价，前端传入金额只作提示（PRD 7.4）
以数据库当前数据为准（商品价、促销、券门槛）
事务失败 → 整体回滚
购物车保持原状，不出现半成功；返回 400 / 409 并提示
重复请求：idempotencyKey + 条件更新（stock >= quantity、券 used=false）保证只生效一次
并发下同一库存 / 同一红包只允许一个订单成功
段 2 · 商家处理（P0 主线 + 商家订单推进支线）接单 / 制作 / 配送 / 完成属本期 P1，以虚线标注；配送进度由订单状态表达
① 商家登录后台
② 登录页与会话守卫（角色 = 商家）
③ 查询本店订单与经营数据POST /auth/login · GET /merchant/orders · GET /merchant/overview、/merchant/analytics
④ 校验商家身份，按 storeId 过滤本店数据（支付前订单对商家不可见）
⑤ 查询本店订单、（可选）聚合统计只计「已支付且未取消」的有效订单
⑥ orders / order_items（商家视图不含他店数据）
⑦ 推进订单状态：待接单 → 制作中 → 配送中 → 已完成PATCH /merchant/orders/{orderId}/status（跳级 409、重复提交幂等）
⑧ 校验当前状态与订单归属，只允许按顺序推进；成功后写订单通知
⑨ 更新订单状态（同事务记录通知）
⑩ orders.status 落库
⑫ 用户端重新查询即见新状态与时间线GET /orders/{orderId}
⑪ 返回最新状态（跨端同步：两端读同一份订单数据）
