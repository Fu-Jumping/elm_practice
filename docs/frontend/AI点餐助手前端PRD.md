# AI 点餐助手前端 PRD

> 本文档描述外卖平台用户端 AI 点餐助手的前端页面与交互设计，配合后端接口 `POST /api/v1/ai/chat` 与 `/api/v1/ai/stream-chat`（见后端契约 §10.6）。

## 1. 概述与定位

### 1.1 定位

「小饿」AI 点餐助手是用户端的对话式点餐推荐入口，帮助用户通过自然语言发现美食、选择商家、挑选菜品。助手**只做推荐与查询，不直接下单、不修改购物车、不处理支付**；用户想下单时由助手引导至对应商家页。

### 1.2 核心价值

- 降低点餐决策成本：用户不知道吃什么时，通过对话快速获得个性化推荐
- 跨越商家列表浏览：直接说"我想吃辣的"即可跨店检索辣味菜品
- 多轮上下文记忆：追问"还有什么喝的"时，助手记得之前讨论的是哪家店

### 1.3 技术基础

| 项 | 说明 |
| --- | --- |
| 后端接口 | `POST /api/v1/ai/chat`（非流式）、`POST /api/v1/ai/stream-chat`（SSE 流式） |
| 会话标识 | `sessionId`：**由前端生成并随每次请求携带**（契约 §10.6 允许传入；`/stream-chat` 只回文本分片、不回 `sessionId`）。若 `/chat` 回显了不同的 `sessionId`，前端切到后端 id 并在新 key 下保存当前消息 |
| 数据来源 | 后端启动时从业务库加载全部在售商家与商品生成知识库，注入大模型上下文 |
| 大模型 | DeepSeek，经后端代理调用，前端不接触 API key |

## 2. 入口设计

### 2.1 主入口：首页悬浮球

- 位置：首页右下角悬浮（不遮挡底部 Tabbar），距底部 Tabbar 上方 16px
- 形态：圆形按钮，直径 56px，亮橙色 `#ff5a1f` 背景，白色对话气泡图标
- 交互：点击展开 AI 对话页（全屏覆盖，从底部滑入）
- 隐藏规则：在商家详情页、购物车页、订单页等非首页不显示悬浮球（避免遮挡操作）

### 2.2 辅助入口：首页搜索框

- 首页搜索框右侧增加"AI 推荐"小按钮（亮橙色文字 + 图标）
- 点击进入 AI 对话页，预填提示词"帮我推荐今天吃什么"

### 2.3 我的页面入口

- "我的"页面功能列表增加"AI 点餐助手"条目，带对话图标
- 点击进入 AI 对话页

### 3.2 顶部栏

- 左侧返回箭头，返回上一页
- 中间标题"小饿 AI 点餐助手"，副标题灰色小字"智能推荐 · 只做建议不下单"
- 右侧无操作按钮

### 3.3 消息列表区

- 消息按时间正序排列，最新消息在底部
- 新消息到达时自动滚动到底部
- 用户消息右对齐，亮橙色气泡，白色文字
- AI 消息左对齐，浅灰色背景气泡，深色文字，带头像（🤖 或品牌图标）
- AI 回复中显示"正在思考..."加载动画（三点跳动），流式输出时逐字显示

### 3.4 快捷提问栏

- 位置：输入框上方，横向滚动
- 预设问题（可点击直接发送）：
  - "不知道吃什么，帮我推荐"
  - "我想吃辣的"
  - "有什么便宜的"
  - "肯德基有什么"
  - "今天有什么优惠"
- 最多显示 5 个，超出横向滚动

### 3.5 输入区

- 输入框：圆角，占位文字"输入你想吃的，比如 我想吃辣的"
- 发送按钮：亮橙色背景，白色纸飞机图标，输入为空时置灰禁用
- 支持回车发送（移动端虚拟键盘回车）

## 4. 消息展示规则

### 4.1 AI 回复内容格式化

AI 返回的 Markdown 文本需前端渲染：

| 元素 | 渲染方式 |
| --- | --- |
| 加粗 `**文字**` | 加粗显示 |
| 列表 `- 项` | 无序列表，缩进 |
| 价格 `¥19.50` | 原样显示，可高亮 |
| 换行 `\n` | 保留换行 |

### 4.2 商家名可点击

AI 回复中提到的商家名称渲染为可点击链接（前端通过商家名匹配商家列表拿到 storeId）：
- 点击跳转到对应商家详情页（如"肯德基宅急送"→ `/store/m002`）
- 视觉：亮橙色文字
- AI 回复文本本身不出现商家编号（如 `m002`），编号仅用于前端路由匹配

### 4.3 流式输出

- 优先使用 `/stream-chat` 接口（SSE），AI 回复逐字显示
- 流式输出时，AI 气泡实时追加文字，不显示"正在思考"
- 流式结束后保存完整消息到本地会话记录
- 若 SSE 不支持或失败，降级到 `/chat` 非流式接口

## 5. 会话管理

### 5.1 会话标识

- 首次进入对话页时，**前端生成** `sessionId` 并随请求携带（2026-09-15 口径修订：原写「调用 `/chat` 不传 `sessionId`、后端返回新的 `sessionId`」与实测不符——契约 §10.6 的 `/stream-chat` 只回文本分片、不回 `sessionId`，按字面实现则首次回复无法走流式；契约 §10.6 明确「不传则后端基于 HttpSession 生成，传即采用」）
- 前端将 `sessionId` 保存到 localStorage（key: `ai_session_id`）
- 后续请求携带该 `sessionId`，实现多轮记忆
- 用户主动清空对话时，清除 localStorage 中的 `sessionId`，下次进入生成新会话

### 5.2 本地消息记录

- 消息记录存 localStorage（key: `ai_messages_{sessionId}`），最多保留最近 50 条
- 进入对话页时从 localStorage 恢复历史消息展示
- 新消息追加到本地记录
- 不依赖后端查询历史消息（后端只存不查，前端自管理展示）

### 5.3 清空对话

- 顶部栏可增加"清空"按钮（或在"我的"页面设置里）
- 点击后：清除本地消息记录 + 清除 sessionId，显示欢迎语
- 不清空后端会话记录（后端按 sessionId 隔离，重新生成即隔离）

## 6. 欢迎语与空状态

### 6.1 首次进入欢迎语

首次进入对话页（无历史消息）时，AI 自动发送欢迎语：

> 你好呀～我是小饿，你的 AI 点餐助手 👋
>
> 不知道吃什么？告诉我你的口味或预算，我来帮你挑！
>
> 试试问我：
> - 我想吃辣的
> - 推荐肯德基的菜品
> - 有什么便宜又好吃的

### 6.2 加载状态

- 发送消息后，AI 气泡位置先显示"正在思考..."三点动画
- 流式输出开始后，三点动画消失，逐字显示回复

### 6.3 异常状态

| 场景 | 前端处理 |
| --- | --- |
| 网络断开 | 输入框上方提示"网络连接失败，请检查网络" |
| 接口超时（>30s） | AI 气泡显示"回复超时，请重试"，可点击重发 |
| 后端 503（未配 key） | 顶部 Toast 提示"AI 助手暂不可用，请稍后再试" |
| 后端 400/500 | AI 气泡显示"出了点小问题，请换个说法试试" |

## 7. 交互流程

### 7.1 主流程

```
用户点击悬浮球 → 进入对话页 → 显示欢迎语 → 用户输入问题
→ 发送请求（携带 sessionId）→ 流式接收 AI 回复 → 渲染消息
→ 用户继续追问 → 多轮对话
```

### 7.2 追问商家详情

```
AI: 推荐肯德基宅急送的香辣鸡腿堡 ¥19.50...
用户点击"肯德基宅急送" → 跳转到商家详情页
```

### 7.3 快捷提问

```
用户点击 [我想吃辣的] → 自动填入输入框并发送
→ AI 返回辣味菜品推荐
```
