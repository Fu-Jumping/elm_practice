# UI 复刻经验总结与本项目执行约定

> **定位**：用户端开始任何 UI 实现前必须先阅读本文。商家端为桌面后台、不承担 1:1 复刻义务（见 `docs/PRD.md` 7.16.2），不适用本文的复刻要求，但第 2 节的通用工程教训仍可参考。
>
> **评审口径（2026-09-11 负责人拍板，与 PRD/SRS 一致）**：PRD/SRS 的「原型说明」是**基础口径**，最终实现是其**超集**——比原型说明**更细或更多**（样式与像素细节更精细、状态更完整（加载态/空态/错误态/边界）、交互反馈更丰富）**不视为复刻不到位或与原型说明不一致**，评审与交叉验收**不得据此判偏差**；反之**缺少**原型说明列入的基础内容按偏差处理。**新增页面、新增字段或改变业务规则**仍须按 `docs/project/项目规则.md` R7 走口径确认。

## 1. 核心结论

在让 AI 按设计稿 1:1 复刻界面的既往实践中，最大的共性错误是：**把设计稿当成"视觉参考"，而不是必须逐项落实的"视觉真源"**。

起点一旦错了，后续会连环出现同类问题：

- 图片、贴图、图标素材没有系统迁移，用文字、单字、色块临时占位。
- 设计稿的通栏、分区被通用卡片组件替代，或卡片多层嵌套，与原稿结构不符。
- 页面"能跑通流程"但视觉与设计稿差距明显，返工成本远高于一次做对。
- 设计稿的固定画布尺寸、绝对定位未经运行态校正，带来滚动、抖动、裁切等问题。

相对正确的起点是：

- 先明确"哪些口径高于设计稿"（产品需求取舍、PRD 删除项），其余视觉细节一律按稿复刻。
- 先建映射与清单（页面↔设计稿映射、素材清单、截图比对基线），再动手写页面。
- 按设计稿的 DOM 层级与样式逐项转写，然后才接入真实交互、路由和状态。
- 每页完成后截图与设计稿比对，多视口检查通过才算完成。

## 2. 常见错误模式与正确做法

以下模式来自既往实践的复盘，均为一般化描述，按"现象 → 根因 → 正确做法"组织。

### 2.1 "先跑通再美化"

- 现象：先用通用组件和简化样式把主链路搭通，计划"以后再对齐视觉"，结果视觉长期偏离设计稿，最终整批返工。
- 根因：把"能运行"当成了页面完成标准；没有建立映射、素材清单和截图比对门槛。
- 正确做法：不允许"先通用后美化"；没有设计稿映射、素材映射和截图证据，页面不算完成。

### 2.2 卡片化与嵌套滥用

- 现象：设计稿中的通栏区域被包进卡片壳；圆角通栏只被加宽、仍看得出卡片边界；出现多层卡片嵌套，偏离原稿层级。
- 根因：用通用 `.card/.panel` 思维替代设计稿实际结构；只调宽度，不同步检查圆角、边线、背景与父级留白。
- 正确做法：设计稿没有卡片壳就不要加壳；判断是否卡片必须看圆角、阴影、边框、背景与父级 padding 的组合，不能只看宽度。

### 2.3 素材缺失与占位

- 现象：图标用单字、符号或色块占位；横幅卡、权益卡等只保留文字、缺少原稿材质；插图与头像类贴图未按稿使用；数据源里存的裸素材文件名或相对路径被直接塞进 `img`，运行时 404；用本地替代素材顶替原稿图片时宽高比不一致，`cover` 裁切后构图跑偏。
- 根因：实现前没有素材清单；素材没有统一复制进工程公共目录；组件实现时默认用文本和 CSS 占位；素材路径缺少统一解析层，替代素材未按原稿宽高比核对。
- 正确做法：实现前列出页面全部 `img`、背景图、SVG/PNG；素材先行复制到工程允许提交的目录并统一引用方式；素材缺失先补素材，不允许文字或色块临时代替；任何来自数据源的图片字段先经统一路径解析再渲染；替代素材必须核对宽高比与裁切表现（`contain`/`cover` 按构图取舍）。

### 2.4 浏览器默认样式破坏布局

- 现象：转写后与设计稿像素差异大、元素位置偏移；真实 `input`/`button` 显示浏览器默认外观；`p` 标签默认 margin 把文本顶偏；同一容器里的状态标签（如默认/普通）沿用了同一样式，状态色差异丢失；导出稿里固定宽度加大 padding 的 Tab 标签，放进真实中文文案后出现换行。
- 根因：设计稿导出样式默认没有浏览器默认 margin；设计稿里的"假输入框"转成真实表单控件后没有局部重置原生样式；状态标签复用了同一文字容器样式；固定宽度被大 padding 压缩后中文可用宽度不足。
- 正确做法：在复刻页面的作用域内重置 `p`、`button`、`input`、`textarea`、`select` 的默认样式；checkbox、switch 等用"隐藏真实控件 + 自绘视觉"的方式保留交互与状态，视觉层级不变；状态类标签按稿拆分状态样式；固定宽度容器内的中文文案用行盒验证不换行（居中 + 禁换行），不能只看元素总高。

### 2.5 设计稿画布高度直接搬运

- 现象：内容并不超屏的短页面出现空滚动；滚动把固定顶栏一起带走；一级页之间高度策略不同，切换时顶部抖动。
- 根因：设计稿的固定画布高度被直接当作运行页高度或 `min-height`；body 级滚动与内部滚动混用；固定顶栏/底栏没有统一的容器策略。
- 正确做法：有固定顶栏/底栏的页面优先 `height: 100dvh; overflow: hidden`，只让内容区滚动；一级页面统一页面壳与滚动容器策略；牢记"设计稿画布高度 ≠ 运行页高度"，每个页面都要跑多视口滚动检查（短页无 body 级空滚动，长页固定栏位置不变）。

### 2.6 多页共享组件不统一

- 现象：各页底部导航的图标尺寸、选中态、安全区高度不一致；顶栏高度、边框、固定方式各异，切换时观感跳变。
- 根因：各页各自保留导出稿里的底栏/顶栏实现；不同导出稿图标的 viewBox 与留白本就不同。
- 正确做法：底栏/顶栏提升为统一组件与统一图标资源（统一图标外框尺寸与选中态表现）；修改共享组件时，所有使用页同步检查静止态与切换态。

### 2.7 复合滚动页（长列表 + 分类导航 + Tab 吸顶）

- 现象：Tab 切换时共用头图与 Tab 抖动或竖排；吸顶层、左侧分类栏被滚走；内容区出现不该有的滚动条；内容不足时滚出大块空白。
- 根因：把一个复合页拆成多套页面结构，切换时共用头部被销毁重建；外层滚动、sticky 层级、内层滚动边界没有先设计；用 `preventDefault + scrollBy` 强制接管滚动导致卡顿。
- 正确做法：先设计滚动容器与 sticky 层级，再写交互；共用头部只切换下方内容、Tab 禁止换行；"外层先自然滚到吸顶线，之后内层滚动"；分类点击覆盖两条路径（从页面顶部点击、内层已滚动后点击）都要正确定位；隐藏不应出现的滚动条。

**落地配方（2026-09-08 商家详情页实测沉淀，双视口 390x568 / 390x844 验证）**

- 滚动交接靠「高度算式」而非滚动接管：内层滚动区高度取 `calc(100dvh - 顶部栏高 - Tab 栏高)`，外层页面总高即为「横幅 + 视口」，最大滚动量恰好等于「横幅高度 + Tab 上边距」——外层自然停在 Tab 吸顶线，再滚就落到内层，无需 `preventDefault`。
- 吸顶线用 `position: sticky; top: <顶部栏高>`；顶部栏与 Tab 都必须有不透明背景，否则滚动内容会透出。
- 点餐区两栏（左分类栏、右商品列表）各自 `overflow-y: auto`，底部按固定购物车栏高度留白（本页 56px），保证最后一项能完整滚到栏上沿之上。
- **滚动高亮不要用 `IntersectionObserver` 的交集结果直接判定**：它只上报"交集状态变化"，长分区内滚动、或从底部滑回顶部时状态不变、回调不触发，高亮会滞留在错误分类。做法是让观察器只当触发源，真正判定用偏移量（取最后一个 `offsetTop <= scrollTop` 的分区，滑到底部时特判最后一个分区）。
- **sticky 的分区标题不能作为观察目标**：它吸顶后永不离开视口，观察它永远等不到"离场"事件；应观察分区容器。
- 点击分类要先把外层滚到吸顶线、再滚内层（顺序反了会被外层滚动打断定位）；程序化滚动期间用一个短锁（约 600ms）抑制滚动高亮回调，避免高亮中途跳变。
- 该页 px 值经 `postcss-px-to-viewport` 统一换算为 vw，`calc()` 内的 px 同样换算，因此固定高度与 vw 缩放天然一致；改高度算式时不要混用未换算单位。

### 2.8 弹层与状态链路不贯穿

- 现象：弹层内部出现可见滚动条、关闭按钮与背景重叠看不清；弹层内的选择对列表金额无影响；列表行点击行为未定义；下单金额与弹层选择对不上；弹层展开后，仍然可见的触发入口再点无反应，弹层收不起来。
- 根因：弹层初版只展示基础数据；聚合与计价逻辑缺少维度；行组件只作展示，没有定义打开行为；入口只实现了打开分支，没有实现收起。
- 正确做法：弹层、行点击、toggle 等行为在实现弹层时就定义进组件；金额类链路（弹层选择 → 列表小计 → 确认页 → 明细）逐环验证一致，不能只验证"能加入"；展开态仍可见或有同形态底栏的触发入口必须支持再次点击收起。

### 2.9 控件只有外观没有行为

- 现象：更多、定位、上传、筛选等控件有样式无反馈；同一种入口在某几页有效、另几页无效。
- 根因：复刻优先还原静态视觉，没有同步给每个控件分类定义行为。
- 正确做法：每个可见可点控件必须归入六类之一——跳转 / 弹层 / 状态切换 / 表单反馈 / 弱提示 / 禁用；页面完成前做全控件点击审计；入口统一指向并支持返回来源页。

### 2.10 品牌色与语义色混用

- 现象：按钮、线条、图标沿用设计稿遗留的深红、紫红，与品牌强调色混杂。
- 根因：没有区分"品牌强调色"与"语义色（错误/危险/未读）"，也没有建立色值扫描习惯。
- 正确做法：约定品牌强调色与语义色清单（本项目见 `docs/design/设计系统-用户端.md` 实现口径：强调 `#ff5a1f`，红色仅用于错误、危险、未读、售罄等语义）；新增页面默认用品牌色；定期扫描硬编码色值并逐个判断是否语义色。

### 2.11 页面切换动画移动页面壳

- 现象：底栏稳定后，标题栏与主内容在页面切换时仍横向抖动；干脆移除过渡又变成生硬切换。
- 根因：路由过渡动画对包含固定顶栏的页面根节点做了 `translate3d` 之类位移。
- 正确做法：页面切换动画只做 opacity 淡入淡出，不移动页面壳；确需滑动效果时，只作用于不含固定顶/底栏的内部内容层，并先建立裁剪边界、动画期做溢出检查；自动化截图与断言要等过渡动画结束后再取，选择器出现不等于过渡结束。

### 2.12 固定尺寸组的小屏裁切

- 现象：按 390px 设计稿实现的固定列数、固定宽度文本、不换行标签和小尺寸控件，在 320~375px 视口被裁切或横向越界；装饰性元素的负向定位越出页面边界；同一问题先在一处实现中修复，另一处实现中同类问题仍在。
- 根因：设计稿画布是单一宽度，固定尺寸组没有小屏收缩规则；负向定位没有边界约束；同一问题在两处实现中只修了一处。
- 正确做法：多视口验收必须包含 320px；固定列数在小屏改等分布局、长文本允许收缩或换行、装饰元素留出边界余量；一处修过的溢出问题要同步排查所有同源实现。

## 3. 泛化的 exact 复刻流程

新增或复刻任何"必须对齐设计稿"的页面时，按以下三段执行。

### 3.1 启动前

1. 阅读项目协作约束与入口文档，确认产品需求、删除项和验收口径。
2. 确认是否有已确认的产品取舍覆盖设计稿（有则记录出处，无则按稿复刻）。
3. 找到该页对应的设计稿代码与截图，建立"页面 ↔ 设计稿"映射。
4. 列出全部素材文件并复制到工程允许提交的素材目录，形成素材清单。
5. 盘点设计稿页面清单时，同时核对代码文件、截图、设计说明与无效导出占位，不能只按其中一种文件的数量判断页面数量。

### 3.2 实现时

1. 先转写 exact 视觉层，再接业务逻辑；两者不混步。
2. 保留设计稿的关键 DOM 层级、类名语义、尺寸、间距、圆角、背景、图标与素材。
3. 真实表单控件只能放进设计稿原结构中，并按 2.4 重置浏览器默认外观。
4. 不新增设计稿没有的卡片壳、面板壳、圆角容器或阴影。
5. 产品取舍导致的偏离要记录原因与出处。
6. 控件必须同步补行为（见 2.9），不允许只画外观。

### 3.3 验收时

1. 截图与设计稿比对，关键状态（空态、加载、错误）也要截图。
2. 覆盖多视口（移动端至少 320/360/375/390/430，必要时 768/1024）。
3. 检查横向溢出、文字裁切、图标漂移、素材加载、滚动条、固定栏位置、弹层位置。
4. 检查控制台 error/warn 与开发服务器 overlay。
5. 检查主链路交互：跳转、弹层开关、表单输入、选中状态、金额计算、返回路径。
6. 构建命令通过（如 `npm run build`）。
7. 按 PRD"明确不做项"扫描，确认没有恢复被删除的功能入口或文案。
8. 修复过的问题记入项目的问题修复记录。

### 4.2 无导出稿新建页面的视觉口径（本期用户端无此类页面）

本期用户端新增页面均有导出稿或已入库设计稿，不再有无导出稿新建页；若后续确需新建页面，**不得凭"感觉"或用通用组件简化搭建**，按以下口径新建，并在页面留痕与报告中注明"按设计系统新建（无导出稿）"：

- **画布与视口**：按 390x844 设计（设计宽 390、最小 320），多视口验收沿用 3.3 的 320/360/375/390/430。
- **主色**：品牌橙 `#ff5a1f` 单一来源（设计系统令牌 `primary-container`）；令牌 `primary`（`#ae3200`）只作深色锚点，不直接用作界面主色；语义红仅用于错误、危险、未读、售罄——取消订单属破坏性操作，其确认按钮与"已取消"状态可用语义红，其余按钮仍用品牌橙。
- **圆角与形状**：标签与输入框 4px，卡片与容器 8px；**禁止 pill/胶囊按钮**（设计系统 Shapes 明确禁止）。
- **间距**：4px 基础单位；页面边距 12px，模块间距 12px，卡片内边距 10–12px，控件间距 8px。
- **层级与边线**：页面浅灰底 + 白色内容面；卡片用 1px `#E5E5E5` 边线，不加环境阴影；取消订单确认以底部弹层呈现（遮罩 40% 黑，Level 3）；配送信息/状态页已砍（CHG-002），配送进度由订单状态（`DELIVERING`）与订单详情时间线表达。
- **排版**：沿用设计系统字号层级（headline-lg 20/28、headline-md 18/24、body-lg 16/22、body-md 14/20、label-md 12/16、label-sm 10/14）；金额、状态与主操作加粗，次要信息用 `text-secondary`/`text-tertiary`。
- **结构红线**：不得用通用卡片壳替换通栏结构（2.2）、不得用文字或色块替代图标素材（2.3）、不得直接搬运设计稿画布高度（2.5）、每个可见控件必须归入六类行为之一（2.9）。
- **内容边界**：**不出现骑手、地图、实时定位与物流轨迹**；配送进度由订单状态（`DELIVERING`）与订单详情时间线表达（配送信息/状态页已砍，CHG-002）；取消订单确认弹层只做二次确认与取消原因必填，**不出现退款、售后或资金处理**（PRD 明确不做项；设计稿中「优惠券将原路退回」文案已按 2026-09-11 拍板删除）。
- **验收**：按第 5 节最小完成定义执行；无导出稿页面的比对基线是设计系统令牌 + PRD 7.16.1 字段口径 + 本节视觉口径，**结论写"按设计系统新建"，不得写"exact 复刻已通过"**。

## 5. 最小完成定义与常用检查

一个复刻页面只有同时满足以下条件才算完成：

- 页面路径、PRD 范围和设计稿映射明确。
- 素材完整迁移并从工程允许目录加载。
- 关键视口首屏与关键状态接近设计稿。
- 无导出稿页面（本期用户端无；若后续新建）另按 4.2 视觉口径与 PRD 字段新建，截图留档并做多视口检查，结论写"按设计系统新建"，不写"exact 复刻完成"。
- 多视口无明显溢出、裁切、错位；固定栏、弹层、滚动容器行为稳定。
- 所有可见控件有实际行为或明确弱提示。
- 控制台无 error/warn；构建通过。
- 截图已留存；必要问题已记入问题修复记录。

常用检查（工程初始化后按实际目录调整）：

```bash
npm run build
# PRD 明确不做项扫描（词表按当前 PRD 维护）
rg -n "客服|退款|骑手|积分" frontend/user-h5/src
# 非语义红色值扫描（结果人工逐个判断）
rg -n "#[0-9a-fA-F]{6}" frontend/user-h5/src
```

Playwright 临时脚本与截图放在 `test-results/**`（已在 `.gitignore`），不要提交。
