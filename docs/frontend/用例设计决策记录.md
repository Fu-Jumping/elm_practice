## 2. 按批次的设计决策

### 2.1 账号与归一化（A/B/C/D/E，9/4-9/5，负责人拍板清单）

- **B1-B2 金额两位小数**：取 12.5 和整数 20 两个样本——覆盖"补齐小数"与"补零"两条 toFixed 路径。
- **B5 未知状态原样返回**：负责人拍板"绝不让页面显示空白"，宁可显示原始枚举。
- **C2 手机 12 位、C3 含字母**：与 C1（10 位）构成长度上下界 + 字符集三向覆盖，正则 `\d{11}` 的一条用例顶三条字符规则。
- **D1 必填全空一次断言五字段**：验证"逐字段独立提示"而非短路返回（表单校验的常见错误实现）。
- **E1 重复注册 409 后登录态不变**：异常路径同时断言错误与会话状态，防"报错但污染状态"。

### 2.2 首页与商家详情（T1-T18，9/6 负责人拍板清单）

- **T7/T8 字段缺失整块隐藏**：契约缺口字段（距离/优惠标签/预览）不显示 `undefined`——口径来自 PRD"字段缺失隐藏对应字段"。T8 用 m003 刻意缺配做样本。
- **T13 默认选中第一个有商品的分类**：PRD 原文口径；断言"切换后商品列表内容变化"而非仅高亮样式。
- **T14 售罄三断言合一**：样式类 + 按钮 disabled + 库存 0 数据，锁"灰化且禁加购"的整体行为。
- **T16 关店**：用 m004（CLOSED）隔离验证——加购/结算双禁用。
- **T18 去结算校验顺序**：登录 → 购物车非空 → 店铺营业，与 PRD 点餐内容区行逐字对齐；9/7 演进为断言跳转确认订单页（原"暂未开放"占位口径过期）。

### 2.3 地址/金额/确认订单（T19-T30，9/7 第一批）

- **T20 电话 10 位、T21 缺地区不牵连详址**：字段级独立报错，与 D1 同一防短路逻辑。
- **T23-T25 金额三级兜底**：后端计价为准 → 缺失推导（小计+打包费）→ 全缺 0.00。设计理由：TC-ORD-011"后端为准"+ normalizers 约定"缺字段给确定默认值，禁止 undefined 上屏"。
- **M1-M4 mock 后端替身**：mock 的存在意义是"契约行为的本地替身"，因此替身自身必须有测试（400/404/计价/清购物车）。**教训固化**：mock 响应形状必须与真实后端一致（9/7 白屏根因即形状不一致）。
- **M3 防假绿**：404 断言必须附加业务 message（"地址不存在"），否则与"mock 未注册也返回 404"撞车。
- **T26 不单列打包费行**：PRD 7.4 评审决议（实付含打包费），断言"41.00 出现 + '打包费'字样不出现"双向锁定。
- **T29 成功三件套**：购物车清空 + 跳转 + toast，对应 PRD"成功前不得清空购物车，成功后由明确前端流程清空"。

### 2.4 地址管理/订单查询（T31-T44，9/7 第二批）

- **M7 删除默认地址的自动改派**：构造"新增即最近更新"再删默认，断言新店接替——TC-ADR-004 的"最近更新一条"规则需要可控的更新时序才能测。
- **M8/M10 防假绿**：同 M3，404 必带业务提示断言。
- **T35 删除二次确认**：PRD 明确"删除需要二次确认"，用 `window.confirm` stub 断言确认行为真实发生。
- **T36-T39 编辑双模式**：非法表单不发请求（停留断言）+ 编辑地址不存在返回列表（PRD 顶部栏行），覆盖新增/编辑/异常三态。
- **T40-T42 订单卡三要素**：状态文案/金额两位小数/时间 `yyyy-MM-dd HH:mm:ss` 全部来自接口值（normalizers 出口），点击卡片断言路由参数。

### 2.5 联调对齐批次（T45-T63，9/7 第三批）

- **T45 加购需登录**：真实后端 /cart 401 而来的口径——前端把"登录先行"从去结算扩展到加购入口，静默失败改为引导登录（用户体验层修复，业务规则仍后端兜底）。
- **T56/T57 变量隔离**：关店用例特意选"加购 56 ≥ 起送 30"的组合，隔离起送因素；起送用例选 9 < 20，断言差额"11"精确出现。
- **T58/T59 双场景对照**：同一地址卡在确认订单场景（选中并返回，PRD 873）与管理场景（进编辑）行为不同——两条断言写在同一用例内互为对照。
- **T60"改种子看联动"**：把默认地址 region 改掉后断言定位文字随之变化——证明数据来自接口而非写死文案（比断言固定文案更强的来源证明）。
- **T61 演示地址标记**：PRD"保留默认演示地址并标记为演示数据"，title 属性承载标记。
- **T63 跨店提示**：A 店加购后进 B 店触发一次性提示（消费型读取防重复）；"保留不合并"是契约 §3.4 唯一范围的直接推论。

### 2.6 工具与归一化（L/N/P 系列，9/7）

- **L 系列登录页**：PRD 818-819 行逐条映射（必填逐项/只发一次/请求中禁用/失败保留账号清空密码/演示账号不显密码/已登录按目标地址处理）。
- **N1-N3 真实形状归一化**：fixture 直接用真实后端 JSON（扁平 itemSubtotal/total），白屏根因的回归锁。
- **B6/B7 状态文案**：PENDING_PAYMENT/COMPLETED 来自联调实测的后端状态机（前端文案兜底，口径待 SRS 固化）。
- **P1-P5 图片三级兜底**：接口值优先 → 演示映射 → 占位图，映射表数据来自组长清单（素材版权溯源见清单）。

## 3. 已知简化口径（答辩主动说明项）

| 项 | 简化 | 正路 |
| --- | --- | --- |
| 备注弹层 | 内联输入（≤50 字） | 设计稿为弹层交互，视觉细化任务 |

| 公开页 401 静默 | 无直接用例（mock /cart 恒 200 无法自然注入） | 后端若开启静态映射/联调环境补集成用例 |
