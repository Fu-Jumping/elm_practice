# frontend 文档目录（前端入口）

本目录是前端文档入口，前端专属文档归此；工程代码在仓库根 `frontend/` 下。当前文件：

- `UI复刻经验与执行约定.md` —— 用户端 UI exact 复刻的经验与流程约束（用户端 UI 修改前必读）。
- `前端架构设计与工程约定.md` —— 两端工程架构、请求层、状态管理、测试与通用约定（正式 v1.0，9/3 初始化依据）。

## 1. 前端规划总览

单仓库多目录：用户端与商家端是**同一个仓库里的两个独立工程**，各自从零初始化、独立进程、互不包含对方代码，均通过 RESTful 与 Java 后端 `backend/` 通信（接口统一 `/api/v1` 前缀，本地后端 8080）。

| 子项目 | 目录 | 形态 | 现状 |
| --- | --- | --- | --- |
| 用户端 | `frontend/user-h5/` | 移动 H5，顾客点餐主链路 | 未初始化，计划 `npm create vue` 从零创建 |
| 商家端 | `frontend/merchant-admin/` | 桌面 Web 后台，桌面优先 ≥1280px，不做移动端 | 未初始化 |

## 2. 技术选型

| 端 | 项 | 选型 | 理由（一句话） |
| --- | --- | --- | --- |
| 用户端 | 框架 | Vue 3 | 移动 H5 主框架，Composition API 便于逻辑复用 |
| 用户端 | 构建 | Vite | 冷启动与热更新快，适合课程小团队快速迭代 |
| 用户端 | 状态管理 | Pinia | Vue 3 官方推荐，API 简单、类型友好 |
| 用户端 | 路由 | Vue Router | Vue 官方路由，与组件体系无缝衔接 |
| 用户端 | 请求 | Axios | 拦截器统一处理 Cookie 凭据（`withCredentials`）、错误与 `/api/v1` 前缀 |
| 商家端 | 框架 | React 18 | 桌面后台组件化开发，生态成熟 |
| 商家端 | 构建 | Vite | 与用户端统一构建工具链，降低协作心智成本 |
| 商家端 | UI 库 | Ant Design 5 | 中后台表格/表单开箱即用，`ConfigProvider` 配置主题色 |
| 商家端 | 状态管理 | 待定 | 商家端以增删改查为主，暂不预设状态库，9/3 工程初始化时定稿 |

## 4. 注意事项

- **品牌橙 `#ff5a1f`**：普通红色按钮、图标、logo、线条统一用亮橙；仅错误、危险、未读角标等明确语义红可保留红色。商家端经 AntD `ConfigProvider` 配置主题色。
- **用户端 exact 复刻**：UI 实现必须按《UI复刻经验与执行约定.md》执行，不得先用通用组件简化搭建。
- **商家端不 1:1 复刻**：不承担设计稿 1:1 复刻义务，实现以 PRD 的字段列、规则列和接口契约为准。
- **校验分层**：前端校验只做用户体验层，业务规则一律由后端兜底校验。
- **接口适配集中**：页面不直接解析原始响应；请求发送、响应拆包和字段归一化统一放在服务层；业务编号格式以契约为准，页面不得自行裁剪或拼接。
- **时间格式**：全项目统一 `yyyy-MM-dd HH:mm:ss`（东八区）。
- **TDD 两段式**：同一功能的业务代码与测试代码不得由同一 AI 一次性生成；测试场景由人设计，AI 只辅助脚手架。
- **Git 纪律**：改代码走特性分支 + PR；提交信息用中文（feat/fix 等类型标识可用英文）。
