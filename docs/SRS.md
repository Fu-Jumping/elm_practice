日期：2026-09-01。状态：**骨架已建立，章节已认领（2026-09-02）**：除组长保留部分外，正文主笔为后端 B（林晨）。

## 0. 文档效力、写作纪律与分工（先读这一节）

- **效力**：SRS 写"系统必须表现的行为和验收条件"。唯一需求源是 `docs/PRD.md`；SRS 不发明需求。与 PRD 或 `docs/backend/后端接口契约.md` 冲突时，先由小组共同修订，不得用代码反推需求。
- **写作纪律（三条）**：
  1. **引用不复述**：PRD 已写死的规则（如 7.4 优惠计算顺序、7.6 订单状态表）只写"见 PRD 7.x"；接口字段引用《后端接口契约》章节号。PRD 说不清楚的，SRS 必须补齐；PRD 说清楚的，只引用不复制。
  2. **异常边界全集**：每个功能需求枚举完整的异常与边界条件（缺参、非法值、越权、不存在、状态冲突、重复提交），这是 9/4 首批失败测试的直接输入。
  3. **可测验收条目**：每条需求带"正常场景 + 异常场景"验收条目，逐条可对应测试用例。
- **写作参考（外部模板，2026-09-02 组长指定）**：章节组织与图表深度可参考《软件需求规格说明书（SRS）标准模板与编写指南》（CSDN：[https://blog.csdn.net/He_CSDN2025/article/details/153044305](https://blog.csdn.net/He_CSDN2025/article/details/153044305)）。其九章结构（引言 / 总体描述 / 功能需求 / 非功能需求 / 接口需求 / 数据需求 / 其他需求 / 验收标准 / 附录）与本骨架基本对应，可采纳的形式：数据需求章按"数据字典 + ER 图 + 存储策略"三节组织、总体描述配系统上下文图、文末附变更记录表（版本/日期/修改人/说明）。

## 1. 引言

目的、范围、术语表；引用文档清单：PRD、接口契约、设计系统（`docs/design/` 用户端与商家端两份；实现真源另见 `docs/design/exports/**` 代码导出快照）、TDD实施规划；文末可按外部模板附**变更记录表**（版本/日期/修改人/说明）。**待填。**

## 2. 需求追踪矩阵

需求追踪矩阵是一张四列对照表：**每条系统需求编号（FR-xx）→ PRD 出处章节 → 承载该需求的契约接口 → 覆盖它的测试用例编号**。作用有二：①答辩时证明"每条需求都有实现载体和测试"，是展示需求闭环的核心证据；②防止漏实现、漏测试——矩阵里任何一行空着，都说明有需求没落地。操作方式：后端 B 写第 4 章时给出 FR 编号，组长据此建表回填；有 FR 没有测试用例的行，在 9/4 提交前补齐或说明原因。

按 PRD 六类基础 P0 能力逐条编号 FR-xx，建立"FR → PRD 章节 → 契约接口 → 验收条目"对照表。**待填。**

## 3. 总体描述

角色与权限矩阵（用户 / 商家，Session 会话，`401`/`403` 口径）；**系统上下文图**（用户、商家、浏览器/前端工程与后端服务的边界关系，画法可参考外部模板的总体描述章）；运行环境与部署形态；设计约束（单仓库三工程、`/api/v1`、时间格式 `yyyy-MM-dd HH:mm:ss` 东八区、金额两位小数由后端计算）；假设与依赖。**待填。**

## 4. 功能需求

按 PRD 六类能力分节：账号与角色、店铺与商品、地址、购物车、订单、商家端管理。每条需求建议格式：

```text
FR-xx <名称>（来源：PRD 7.x；接口：契约 3.x）
描述：<输入 / 处理 / 输出>
正常验收：<条目>
异常验收：<逐条枚举：缺参、非法值、越权、资源不存在、状态冲突、重复提交>
```

## 5. 数据需求

按外部模板的"数据需求"章组织为三节：

- **5.1 数据字典**：实体、字段、类型、约束、默认值、可空性，用"字段 / 类型 / 说明"表格逐实体列出。
- **5.2 ER 图（实体关系图）**：实体、主外键与关系基数（一对多 / 多对多），用 PlantUML 或 Draw.io 绘制，图源与导出图片一并入库。工程版建表 SQL 与种子数据由后端 B 维护；ER / 实体方案的落点由后端 A、后端 B 商定（见 `docs/backend/README.md`），SRS 此处以需求视角给出即可。
- **5.3 存储策略**：课程规模从简，写清数据库选型依据与数据保留口径即可。

固定演示数据引用契约第 2 章，不复制。**待填。**

## 6. 接口需求

按模块引用契约第 3–8 章章节号，不复述字段表；只补充契约未覆盖的系统级行为约束。**待填。**

## 7. 非功能需求

性能、并发与幂等（重复请求不重复生效）、安全（会话与资源归属校验）、兼容性；课程规模从简，逐条可验证。**待填。**

## 8. 测试与验收

测试策略（单元 / 接口 / 联调）、用例与 FR 的映射、验收标准与通过门槛；联调固定环境与 P0 主链路引用《后端联调验收用例》。**待填。**
