### 4.1 TODO-USER-023｜保真度巡检断言脚本（结构 + 多视口）

**目标**：把 2026-09-08 那次"先跑出 23/23 全红、改完 23/23 全绿"的通栏结构断言，恢复成**仓库内可复跑**的脚本；并补上多视口断言。结课汇报要用"可复跑门禁"口径讲这件事，脚本必须能在本机一条命令跑出结果。

**放哪（推荐）**
- 新增 Playwright 用例：`frontend/user-h5/e2e/design-fidelity.spec.ts`；
- 复用现有配置 `frontend/user-h5/playwright.config.ts`（`testDir: './e2e'`、`channel: 'chrome'`、`webServer` 自动拉起 dev；**先确认 dev 跑在 mock 模式**，否则数据源不同会让断言不稳）；

**断言 A｜结构断言（判定口径不得自创）**
- 判定式（三个条件同时满足才算通过）：**① 满宽 = 壳宽（区块左右边界等于 `.app-shell` 内容宽度）∧ ② `border-radius` = 0 ∧ ③ `box-shadow` = none**。
- 出处：`docs/frontend/UI复刻经验与执行约定.md` §2.2——"设计稿没有卡片壳就不要加壳；判断是否卡片必须看圆角 + 阴影 + 边框 + 背景色 + 父级 padding 的组合，不能只看宽度"。
- 受检区块：原先共 **23 项 / 8 类**（**先 grep 核对类名是否仍在；若已改名，按"语义等价区块"重新定位，并在脚本里用注释写出"旧类名 → 新选择器"映射**）：
  1. 确认订单页 `.co-card` × 4（收货地址区、送达时间、商品明细、备注输入）；
  2. 订单列表页 `.ol-card` × 10；
  3. 订单详情页 `.od-card` × 3（状态区、收货信息区、商品与金额明细）；
  4. 我的页 `.mn-profile`、`.mn-menu`；
  5. 地址列表页 `.al-card` × 2；
  6. 新增/编辑地址页 `.ae-card`；
  7. 商家详情页 `.store-tabs`（点餐/评价 Tab：必须与横幅同底通栏，不能是独立白条）；
  8. 其余按当时留痕补齐到 23 项。
- 结果口径：打印"通过 N / 受检 N"；失败时输出选择器、实测 `border-radius` 与 `box-shadow`，便于定位。

**断言 B｜多视口断言（320 / 360 / 375 / 390 / 430）**
- 视口：320×568、360×640、375×667、390×844、430×932（同一用例参数化）。
- 每个视口至少断言：
  1. **无横向溢出**：`document.documentElement.scrollWidth <= 视口宽`，且不存在 `getBoundingClientRect().right > 视口宽 + 1` 的元素（装饰性元素单独列白名单并注释原因）；
  2. **页面壳宽度 = 视口宽**（`.app-shell`）；
  3. **固定栏**：底部导航/购物车栏贴底可视、未被内容遮挡（`elementFromPoint` 取底部中心像素归属验证）；
  4. **文字不裁切**：关键词抽样（商家名、价格、按钮文案）满足 `scrollWidth <= clientWidth + 1`。
- 依据：约定 §2.12（"多视口验收必须包含 320px"）与 `docs/frontend/前端架构设计与工程约定.md` §6（**几何类断言只能写 E2E**：jsdom 无布局引擎、`getBoundingClientRect` 恒为 0；不得用"断言 CSS 声明字符串"凑数）。
