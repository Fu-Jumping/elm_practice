## 2. 任务行字段

| ID | 任务 | 类型 | 出处 | 负责人 | 状态 | 证据 | 更新 |
| --- | --- | --- | --- | --- | --- | --- | --- |

- **ID 前缀**（只增不复用）：`TODO-USER-` 用户端、`TODO-MER-` 商家端、`TODO-BE-` 后端、`TODO-OPS-` 部署、`TODO-DOC-` 文档与交付。
- **类型**：`缺陷`（必须同时登记 `docs/testing/缺陷跟踪表.md` 并互相引用编号）/ `打磨`（细节雕刻、体验与一致性）/ `未完成模块`（PRD 与契约里尚未落地）/ `技术债`（重构、脚本、环境、文档结构）。
- **出处**：必须可回溯（PRD 章节、FR/TC 编号、契约章节、缺陷编号、会议决议日期）。**没有出处的任务不得登记。**
- **负责人**：**必填，且每行必须有且仅有一名主责人**（协作人写在任务描述里）。
- **状态**：`进行中` / `已完成` / `已冻结`（三态；无"待认领"、无"待验证"——任务一登记就已指定负责人，完成由主责人填证据后直接置为已完成，组长或测试同学在评审/验收时抽查）。
- **证据**：PR 链接、提交号、测试结论、记录文件路径；未完成的行留空。

## 3. 智能体工作协议（所有 AI 代理必须遵守）

1. **开工前**：先读本文件 + 自己负责的板块文件；**只能做**负责人写着自己（本人或本人所属角色）且状态为 `进行中` 的任务，不得自行扩大范围。
2. **执行**：必须按「出处」列回读 PRD / 契约 / TC 用例，不得凭猜测实现；口径变更按 **R7** 在同一 PR 内同步文档。
3. **推进**：任务有进展就更新「证据」列（分支名、PR 草稿、测试结论）与「更新」日期；**发现新问题时直接在本板块追加一行**，缺陷类同时登记 `docs/testing/缺陷跟踪表.md`（缺陷台账写权归测试联调同学）。
4. **完成**：填完整证据并把状态改为 `已完成`；**未收口不得写已完成**（宁可保持 `进行中` 并写明卡点）。
5. **收工留痕**：raw 片段（`docs/record/raw/YYYY-MM-DD/`）里写明本轮新增/更新了哪些 TODO 编号，便于次晨汇总与交接。**同一天同一成员/角色只写一个文件**（`<成员或角色>.md`，后续轮次追加小节），规则见 `docs/project/项目规则.md` §2 第 2 条 2.1–2.3。
6. **禁止**：另建待办清单；删除已完成任务；把任务状态改成未规定的取值。
