### 21:35 AI 点餐助手架构优化（方案 B：静态知识库注入，去掉 Function Calling）

与用户确认方案 A（Function Calling + 实时查库）存在稳定性问题（依赖大模型正确选工具+传参、多轮调用增加延迟和失败率），改为方案 B：启动时从 MySQL 加载全部在售商家与商品生成知识库文本，动态拼入系统提示词，大模型直接从上下文检索回答，零工具调用。

**改动**：
- 新增 `ProductKnowledgeService`：启动时查 stores/categories/products 生成结构化知识库文本（商家评分/月售/配送时长/起送价/配送费/分类/商品价格/标签/销量/库存），首次调用缓存，支持 refresh() 强制刷新
- 改造 `AiChatConfig`：用 `systemMessageProvider` 动态拼接系统提示词 + 知识库，去掉 `.tools(orderingTools)` 绑定
- `AiChat` 接口去掉 `@SystemMessage(fromResource)` 注解（由 systemMessageProvider 接管）
- `OrderingTools` 保留但不再绑定（留作方案 A 回退备份）
