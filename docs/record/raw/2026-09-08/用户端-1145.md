## A 当日进度

- **负责人 Chrome 复现"登录后白板"**（此前 IAB 复核亦多次遇到）——确认真 bug，非环境问题。Console 线索 `GET /me 401` 为未登录状态的正常探活，与白板无因果。
- **排查路径（排除法 + 取证）**：
  1. 排除后端/代理：curl 经 vite 代理完整验证登录→Set-Cookie（JSESSIONID Path=/ HttpOnly）→探活 200 全通；订单接口形状与前端期望一致。
  2. 排除订单页代码缺陷：OrderListView 全链路兜底（接口失败显示"暂无订单"非白板）。
  3. ZCode IAB 无法复现（输入事件管线损坏，三路点击全废），改用 **Playwright 驱动真实 Chromium**（playwright-core + 本机已有 chromium-1234 二进制，--no-save 不入库）建立可编程复现：登录页 → 一键登录 → 等待 5s → 断言 body 文本。
- **根因锁定**：App.vue 根级 `<RouterView><Transition name="page-fade" mode="out-in">`——顶层路由切换（/login → MainLayout）时 out-in 的"旧组件 leave 完成后插入新组件"链路中断：路由 matched 正常（MainLayout+home）、组件对象已解析、无任何报错/rejection，但 router-view 渲染空注释 `<!---->`，body 文本长度 0。**首页↔详情等主布局内子路由切换不触发根级动画故不受影响**——与"每次登录都白板、刷新（整页加载不走 SPA 动画）恢复"现象完全吻合。
- **对照实验三组**（同一复现脚本）：① 去除 Transition → 白板消失；② 保留 out-in 加 :duration=250（绕过 transitionend）→ 仍白板；③ 去 mode="out-in"（默认同时进出）→ 白板消失。判定卡点在 out-in 机制本身的插入链路。
- **修复（c84c4b6，分支 fix/login-blank-transition）**：去除 `mode="out-in"`，保留 page-fade 淡入淡出 + `:duration="250"`。真浏览器复现证据：修复前 body 文本 0 → 修复后 380 字符完整渲染；全量回归 **122 passed (19 files) 全绿**。
- **TDD 例外（如实登记）**：该缺陷为真实浏览器渲染层行为，jsdom 无法复现（L1-L7 登录跳转用例 jsdom 全绿），以真浏览器复现脚本输出作为红绿证据（0 → 380），无法形成 test: 红提交，例外性质同 XA-06，以本片段留痕。
