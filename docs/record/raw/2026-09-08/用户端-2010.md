# 2026-09-08 用户端留痕（商家详情页购物车抽屉「下方空白」缺陷定位，只读排查）

## A. 进度事实

- **范围**：只读排查，**未改任何业务代码/测试代码**；新增文件仅 `test-results/cart-popup-diag/`（该目录已 gitignore，不入库）内的诊断脚本与截图。
- **缺陷现象**：商家详情页点购物车栏展开购物车弹层后，弹层底边与底部购物车栏之间有一条可透视的缝隙，页面内容与购物车栏在缝隙里露出，弹层没有贴到画面底端。
- **定位结论（真浏览器实测：390x844 / 390x568 / 430x900 / 1280x800 四视口）**：
  - 根因在 `frontend/user-h5/src/views/user/StoreDetailView.vue` 的 `.cart-popup`（:1032-1042）：`bottom: calc(72px + env(safe-area-inset-bottom))`；而 `.cart-bar` 高 64px（:1128-1143）。弹层底边距视口底 72px、购物车栏顶边距视口底 64px，两者之间留出 **8px 透明缝**。
  - 实测（390x844，抽屉展开）：弹层 `rect.bottom = 772px`，购物车栏 `rect.top = 780px`，**缝高 8px**；缝隙中点 `elementFromPoint` 栈顶为 `div.cart-popup-mask`，其下一层为 `div.product-item` → 缝隙里露出的正是遮罩之下的商品列表。
  - 层叠关系（弹层 / 遮罩 / 购物车栏同为 `.store-detail-page` 兄弟节点）：弹层 `z-index: 40` > 遮罩 `30` > 购物车栏 `20`；「去结算」按钮中心的 `elementFromPoint` 栈顶同样是遮罩 → 展开态整个购物车栏被遮罩压住（变暗、点击落到遮罩上收起弹层），因此缝隙与底栏都读作「没贴底」。
  - 放大因素：px→vw 换算（`frontend/user-h5/vite.config.ts` 的 pxToViewport，viewportWidth 390）把 8px 缝换成 2.05vw，视口越宽缝越大——1280x800 实测缝高 **26.3px**、弹层底边距视口底 236.3px；同视口弹层高 577.9px、顶边 -14.2px 已溢出视口顶部（`.cart-popup` 无视口内高度约束）。
  - 溯源：该规则自 `f1243a7`（2026-09-07「feat: 购物车弹层与商品行步进器接入 PATCH/DELETE」）引入后未再改动；现有单测 `StoreDetailView.spec.ts` 只断言弹层存在/收起与行数，jsdom 无布局，故几何问题未被覆盖。
- **待负责人确认口径（未改代码）**：① 弹层贴购物车栏上沿（`bottom: 64px + safe-area`，底栏保持可见可点，饿了么式）；② 弹层直接贴视口底（`bottom: 0`，覆盖底栏）。两种都需同步处理遮罩与底栏的 z-index 关系。
- **附带发现（同页，未改）**：`.app-shell` 的 `max-width: 430px` 同样被 px→vw 换算（430/390×100 = 110.256vw），实测 390 视口算得 429.998px、430 视口算得 474.1px、1280 视口算得 1411.28px，桌面预览的 430px 居中约束实际失效；且 `.cart-popup` 用 `left:0/right:0`、`.cart-bar` 用 `left:50% + translateX(-50%) + max-width:430px`，两种宽度策略并存。
