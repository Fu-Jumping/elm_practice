# 2026-09-08 用户端留痕（返回恢复浏览位置：滚动管线 + 首页 KeepAlive 批次）

## A. 进度事实

- **负责人需求**："首页返回时停留原浏览位置，不要弹回顶部"。诊断确认这是 9/7 T65/T66 需求从未真正生效的缺陷：
  - 取证（Playwright 真浏览器）：进店前 `.app-main scrollTop=800` → 返回后 `=0`；`window.scrollY` 恒 0。
  - 根因三层：① 滚动发生在 MainLayout 的 `.app-main` 独立容器（壳 100dvh overflow hidden），vue-router `scrollBehavior` 只滚 window 从未生效（T65/T66 仅单测函数返回值，注释自认"jsdom 无真实布局"）；② MainLayout 旧 watch 每次路由变化强制置顶，返回也中招；③ 返回时首页重挂载 + 异步拉数，立即恢复会被骨架屏高度钳制。
- **修复**（分支 `fix/home-back-scroll-restore-tdd`，3 提交，基于 origin/main）：负责人拍板"KeepAlive + 滚动管线"方案：
  - 新增 `router/navHistory.ts`：按 history 条目号判 back/forward/push/replace（纯函数可单测）。
  - MainLayout：滚动管线替代强制置顶——scroll 记录各路由停留位置；back/forward 恢复 / push·replace 置顶；`overflow-anchor: none` 关浏览器滚动锚定；RouterView 包 `KeepAlive(include HomeView)`。
  - HomeView：`defineOptions({name:'HomeView'})` + `onActivated` 重读列表（首激活跳过防双请求）。
  - **三重防钳制/防污染**（全部真浏览器取证所得）：beforeEach 快照恢复目标并锁记录（换页瞬间浏览器内部滚动触发的事件不可信）；双帧等待 + 120/360ms 补赋值（KeepAlive 插回页面高度分帧长回 844→1614，单次赋值 842 被钳到 171）；480ms 回写权威值防记录污染。
  - 取证方法留档：scrollTop setter 劫持（区分 JS 赋值与浏览器内部调整）、rAF 逐帧采样（`test-results/register-smoke/debug-scroll*.cjs`，不入库）。
