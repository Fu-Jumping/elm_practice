## A. 进度事实

- **按负责人要求做了一次用户端主链路演示前巡检**（覆盖演示脚本 S1–S6 与常见交互），结果汇总到本地归档 `docs/_archive/2026-09-08-用户端主链路演示前巡检问题清单.md`（该目录 gitignore，属本地留档）。
- **巡检方式**：Playwright + 系统 Chrome 真浏览器脚本 `test-results/main-flow-audit/audit.cjs`（不入库），跑 **mock 模式**（5173）与 **real 模式**（5174：本地起后端 `mvn spring-boot:run` 连服务器库 `82.157.137.114`，前端经 Vite 代理同源），视口 390x844 与 390x568。
- **结果**：mock 390x844 34/34、mock 390x568 34/34、real 390x844 37/39 通过；主链路（登录→进店→加购→购物车栏/弹层→确认订单→提交→订单列表/详情→我的/地址）**功能可用**。
- **拓出 2 个会影响演示的缺陷（real 模式才暴露）**：
  1. **首页无「临时闭店」标识**：老胖烧烤（`TEMPORARILY_CLOSED`）与其他店展示一致，无标识/置灰；PRD 810 要求卡片显示最新状态，演示 S1 讲解词依赖该标识（HomeView 全文未引用 status）。
  2. **详情页对临时闭店不生效**：`StoreDetailView.vue:40` 只判 `'CLOSED'`，真实值为 `TEMPORARILY_CLOSED` → 无休息提示、加购与结算未禁用；违反 PRD 812「商家关闭时禁用加购、结算」与 PRD 417。
- **根因（防复发）**：mock 的 m004 写成 `'CLOSED'`，真实种子为 `'TEMPORARILY_CLOSED'`——mock 自测全绿、真机才红；建议 mock 取值与真实枚举对齐并补用例。
- **另记录**：S4 模拟支付分支不可用（无支付页，订单停在待支付）；订单状态文案（进行中/待支付/已完成）与演示讲解词（待接单/已接单/备餐中）不一致；肯德基种子 5 商品 1 分类（清单要求 ≥6/≥2）；预置订单缺「待接单」；演示库已有 10+ 测试订单（本次巡检又建 2 条）；服务器 8080 后端当前不通；未登录访问详情会打 401；Git Bash 下 `VITE_API_BASE_URL=/api/v1` 被 MSYS 转成 Windows 路径导致全站 HTTP 0（本次踩到，已用 `MSYS_NO_PATHCONV=1` 规避）。
- **环境现状**：本地后端（8080，连服务器库）与 real 模式前端（5174）本轮为巡检而起，仍在运行；mock 前端 5173 亦在运行。

## B. AI 使用点

1. **真浏览器巡检代替目测**：用脚本遍历主链路并做几何/文案断言（卡片数、禁用态、金额、状态文案、横向溢出），比人工点一遍更易发现「mock 绿、真机红」这类差异。
2. **双模式对照**：同一脚本跑 mock 与 real，直接定位到「mock 数据取值与真实枚举不一致」这一根因。
3. **口径核对**：把发现逐条回对 PRD 行号与演示方案条目，区分「缺陷 / 脚本口径不一致 / 准备项」，便于负责人按影响面决策。
