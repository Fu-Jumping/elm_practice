# 2026-09-08 组长留痕（确认订单页地址新增断链缺陷修复）

## A. 进度事实

- **来源**：负责人反馈「支付页面把所有地址都删了，点添加地址没法添加，得退出去添加再回来」，先定位、确认后再动手。
- **定位（三处断链 + 一处隐患）**：
  1. `ConfirmOrderView.vue` 无地址引导块（`co-address-missing`，195 行）是纯静态 section、无 `@click`，点「去添加 ›」完全无响应——直接原因（有地址分支的地址卡有 `@click="pickAddress"` 对照）；
  2. `AddressListView.vue` 的 `goNew()` 跳新增页时丢弃 `select/storeId`，选择模式来源上下文中断；
  3. `AddressEditView.vue` 保存后固定 `push` 管理态地址列表，不回选择回填链路，用户新增完仍回不到确认订单页；
  4. 附带隐患：`ConfirmOrderView.vue` 的 `selectedAddressId` 为 setup 一次性读取常量（非响应式），当前靠「换路由记录即重挂载」侥幸生效。
- **测试缺口**：T28 只断言提示存在与提交禁用、未断言引导可点击；T58 覆盖选择模式点地址卡回填，但未覆盖选择模式下的新增入口——本轮补齐。
- **修复（TDD 红绿两端）**：
  - `10c384c test:` 新增 T60（无地址点引导进选择模式）/ T61（选择模式新增入口透传 select/storeId）/ T62（选择模式新增保存后回确认订单页并回填）→ **红端取证 `3 failed | 18 passed`**，三例失败点即上述三处断链；
  - `bccb183 fix:` 三处实现修改 + `selectedAddressId` 改 `computed` → **绿端 `21 passed`**（同三文件），用户端全量 **144 passed / 22 文件**，`npm run type-check` 退出码 0。
- **行为口径**：确认订单页无地址点引导 → 地址列表选择模式 → 新增 → 保存后**直接回确认订单页并回填本次新增地址**（用 `router.replace`，避免返回到已保存的表单页），不再落到管理态列表；管理场景新增/编辑行为不变。
- **分支与合入**：`fix/confirm-order-address-add`（含 test: / fix: / docs: 三笔），经 PR 合并 main。
