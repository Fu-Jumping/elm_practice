
## 01:20 商家端消息页布局修复（展示阻塞，实测几何取证）

**问题**：消息页外壳无高度约束 → 整页被会话列表撑高、左栏不能独立滚动、消息区死高 490px、**回复输入框被推到页面很下方**（录制演示视频时实测滚 5000+px 才够得到，导致"商家回复顾客消息"无法录制/使用）。

**改动**（`frontend/merchant-admin`，仅布局，不动任何接口/状态管理）：

- `src/App.css`：`.chat-layout` 改为 `height: var(--chat-h, …) + min-height:0 + overflow:hidden + grid-template-columns: clamp(240px,22vw,320px)`；`.conversation-list` 加 `min-height:0; overflow-y:auto`；`.chat-panel` 去掉 `justify-content:space-between` 改 `min-height:0`；`.message-timeline` 改 `flex:1 1 auto; min-height:0; max-height:none`（删掉 490px 硬编码）；新增 `.chat-composer`（`flex:none` + 上边框）与 `.chat-empty`（区域内居中）；会话项压成两行（标题行 `ellipsis`）。
- `src/FeaturePages.tsx`（`MessagesPage`）：外壳挂 `ref`，`useEffect` 内按 `getBoundingClientRect()` 实测计算 `--chat-h = innerHeight − shellTop − Card下内边距 − Card下外边距 − 16`，并挂 `window.resize` + `ResizeObserver`（jsdom 无该 API 时才跳过，避免单测环境报错）；回复框由单行 `Input` 改 `Input.TextArea autoSize={{minRows:1,maxRows:4}}` 并包进 `.chat-composer`（长文本不再撑高，`Shift+Enter` 换行、`Enter` 发送、`maxLength` 不变）；消息区加"仅在用户已贴底时自动滚到底"；两个 `Empty` 居中。

**改前实测（部署版本 `20260915-d11c1f0`，与改后同口径脚本、同视口）** — 视口 1359×748：

| 左栏能否独立滚动 | **否**：`conversation-list 5955 / 5955` | 能：`4317 / 573` |

| 回复框是否在首屏内 | **否**（bottom 6136 > 视口 748） | 是 |

**取证方式说明**：jsdom 不计算布局，按项目对纯布局项的既有口径（`TODO-USER-123`）以**实测几何**代替单测——在服务器 dev server 上跑同一份量测脚本（临时文件，不入库），改前用 `git stash` 撤掉修复、改后用修复版，两者在同一环境、同一视口下测量；数值截图随本记录留痕。

**一处按 SRS 优先于 prompt 的偏离（有数据支撑）**：prompt 建议 `Math.max(420, …)` 兜底最小高度，但实测 1022×631 下 420px 下限会把外壳顶出可用空间、整页重新出现 10px 溢出（违反"禁止整页滚动"）。改为不设下限（内部各区靠 `flex + min-height:0` 收缩），三档视口下整页均无滚动。
