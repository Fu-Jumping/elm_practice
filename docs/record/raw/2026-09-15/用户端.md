- **缺陷**：用户端 AI 点餐助手在**真实模式**下模型回复整段挤成一行：`- item` 列表不成列表、`¥19.50 · 店名` 的空格全部消失。**mock 模式正常**（替身是把整段回复切块回调，`\n` 天然保留），故单测与 E2E 全绿也发现不了——测试盲区。
- **出处**：`docs/frontend/AI点餐助手前端PRD.md` §4.1 表格（「换行 `\n` → 保留换行」「列表 `- 项` → 无序列表，缩进」）+ §4.3 流式输出；验收项 AI-FE-04「支持 Markdown 渲染」。
- **根因（线上抓包实证，非推断）**：`POST /api/v1/ai/stream-chat` 每个 token 发一帧 `data:<token>`，**换行 token 落成同一事件内的多条空 `data:` 行**。按 text/event-stream 规范，一个事件的数据 = 其内部各 `data:` 行的值以 `\n` 连接后的结果。原 `ai.ts` 的实现**按行拆、把每行 `data:` 当独立分片、并直接丢弃空值分片**（`if (piece === '' …) continue`），于是换行事件整帧被丢；又因 `line.slice(5).replace(/^ /, '')` 把**属于 token 本身的空格**当字段分隔符剥掉（后端 SSE writer 并不加分隔空格），空格 token 也一起丢。渲染层 `utils/aiReply.ts` 本身正确（首页欢迎语那种本地常量能正确出 4 个块），坏的是流式解析。
- **真实帧证据（线上抓包节选；行间的「空行」即 cat -A 观察到的换行位置）**：

  ```
  data:：
  （空行）
  data:
  data:
  （空行）          ← 两条空 data 行同属一个事件 → 事件数据为 "\n"
  data:-
  （空行）
  data: **
  （空行）
  data: ·
  （空行）
  data:            ← 冒号后**一个空格** = 一个空格 token（不是字段分隔符）
  （空行）
  ```

  同一段流分别用两种解析还原：「正确 SSE 语义」得 **8 个换行**且结构为「一句话 + 3 条 `- **菜名 ¥价格 · 店名**` + 2 段收尾」；「原实现」得 **0 个换行**。
- **修复（`frontend/user-h5/src/services/api/ai.ts`）**：把分帧解析抽成纯函数 `createSseParser` / `feedSse`，按**事件**（空行结束）取值、事件内多条 `data:` 行以 `\n` 连接；尾部不足一行留在 `state.buffer` 跨 chunk 续接（`data:` 本身也可能被网络从中间切开）；**不再剥冒号后的空格**；单条空 data 行的事件无内容、`[DONE]` 仅作兼容分支，两者都不上屏。`realStreamChat` 改为消费 `feedSse`。
- **红绿两端证据（TDD）**：
  - **红端（第一处，换行）**：先在 main 原样实现上跑新用例，AA-7「换行不得被丢弃」、AA-8「任意分片边界都不丢换行」、AA-9「保留换行后渲染层能还原段落与列表」→ **3 failed / 6 passed**；失败信息 `expected '想吃辣的：- **香辣鸡腿堡 ¥19.50**要不要加饮品？' to be '想吃辣的：\n- **香辣鸡腿堡 ¥19.50**\n要不要加饮品？'` 与 `expected [ 'paragraph' ] to deeply equal [ 'paragraph', 'list', 'paragraph' ]`（后者即「用户看到一整段」）。
  - **红端（第二处，空格）**：修好换行后回放发现空格仍丢，再补 AA-10「空格本身是独立 token」→ 该条红，`expected '香辣鸡腿堡¥19.50·肯德基宅急送' to be '香辣鸡腿堡 ¥19.50 · 肯德基宅急送'`——与真实浏览器里看到的丢空格现象逐字一致；改实现后转绿。
  - **绿端**：`src/services/__tests__/aiApi.spec.ts` **10/10 通过**；`npx vitest run` **59 文件 / 475 用例全绿**（修复前 474，本轮 +4：AA-7~AA-10）；`npm run build`（含 `vue-tsc` 类型检查）✓。
