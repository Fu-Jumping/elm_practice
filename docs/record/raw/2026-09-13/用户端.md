## 15:40 （本轮：SHOW-QA-004 复现测量——「缝隙」不成立、「抖动」机制定位）

### A. 进度事实

- **任务来源**：`docs/todo/用户端.md` `TODO-USER-013`（缺陷，SHOW-QA-004）。问题记录 `docs/testing/问题记录/2026-09-10-商家详情页吸顶栏缝隙与抖动.md` 明确写着**操作步骤与证据「待补充精确步骤与截图」**，故本轮先做真实浏览器测量，把缺失的证据补上，再判断是否可修复。
- **测量方法**：Playwright（本机 Chrome）在验收视口 390×844 打开 `/stores/m002`，等待商品与购物车栏就绪后，直接设定外层滚动容器 `.app-main` 的 scrollTop，逐点读取 `.detail-header` / `.store-tabs` / `.cat-rail` 的 `getBoundingClientRect()` 与 `.order-area--locked` 状态。
- **结果一：「缝隙」在本版本复现不了**。吸顶后（scrollTop 230，Tab 贴住 top 56）实测 `tabsBottom = 99.98`、`railTop = 99.91` → **两者相差 −0.07px（细微重叠，非缝隙）**；初始态各区块首尾相接（tabsBottom 329.91 = orderTop 329.91 = railTop 329.91）。差异来源是 px→vw 换算（44px → 43.98px），量级 0.02–0.08px，不构成可见裂缝。→ 该现象很可能已被 2026-09-08 的滚动交接改造（`fix:` a794aac / b421ea5）消掉，问题记录本身也提示「复现时请确认基线提交」。
- **结果二：「抖动」的机制已定位（可复现）**。逐点扫描 scrollTop 发现**锁定态在阈值附近来回翻转、且每次翻转都改变可滚区域**：
  - scrollTop **225**：`locked = true`，`.product-list` 的 `overflow-y = hidden`；
  - scrollTop **229**：`locked = false`，`overflow-y = auto`；
  - scrollTop ≥230：外层滚到底（最大滚动量 230），状态稳定在未锁定。
  即锁定的切换点落在 225–229 之间，而切换同时把右侧商品列表在「不可滚（滚轮作用于外层整页）/ 可滚（滚轮作用于列表）」之间反复切换 → **在阈值附近上下滚动或方向切换时，输入会时而滚外层、时而滚内层，表现为抖动/跳变**。这与负责人描述的「一定条件下（滚动方向切换或快速滚动）出现抖动」一致，也解释了为何模拟器不易复现（需要真实滚轮/触摸序列）。
- **修复方向（未实施，需先定一个 UX 参数）**：给锁定状态加**迟滞（hysteresis）**——越过吸顶线才锁定、回退超过一个死区（建议 8–16px）才解锁，避免在阈值上抖动；同时可把「是否锁定」由「位置阈值」改为「位置阈值 + 方向」双条件。**死区取多少属交互口径**，且该缺陷严重程度仍为「待测试联调同学确认（建议 P2）」，故本轮不擅自改行为。
- **证据产物**：以上为一次性测量（脚本未入库，属排查手段）；结论与数值已写入本小节，可直接回填问题记录的「证据」栏。
- **未收口**：① 抖动修复待定死区参数与严重程度确认；② 问题记录里「等待测试联调同学确认编号与严重程度」仍未发生（`SHOW-QA-004` 台账状态「新建」）；③ 建议把「阈值附近锁定态翻转 + overflow 切换」写成一条可复跑的断言（加进保真度巡检或滚动交接受用例）后再修。
