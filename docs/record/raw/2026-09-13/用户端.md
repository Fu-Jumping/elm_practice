- **缺陷复现与根因（先定位再动手）**：`HomeView.vue` 的预览区里右缘渐隐 `<span class="product-fade">` 是**无条件渲染**的，与商品数量无关；样式上 `.merchant-products` 用 `width: max-content` + `margin-right: -16px`，展示 3 张（3×72 + 2×8 = 232px）时确实外溢到卡片右缘、渐隐用于盖住溢出的第 3 张，但只展示 2 张（152px）时并不外溢，此时渐隐就没有意义，视觉上像图片被裁切。因此正确条件是「展示 3 张时渲染」。
- **TDD 红端证据**：`test:` 提交 `23a88ac`（仅测试文件）→ 在该提交上复跑 `HomeView.spec.ts` = **1 failed | 16 passed**，唯一失败为新增的 **T72b**（`expected true to be false`，即仅 2 张时仍渲染渐隐）；同时新增的 **T72**（3 张时渲染渐隐）在修复前即为通过，用于锁住既有正确行为不被回归。
- **测试替身**：新增 `dispatchTwoProducts`——包一层原始 `mockDispatch`，把 m002（肯德基，种子 5 个商品）的商品响应截断为 2 个，构造「不足三张」的商家卡；不依赖改种子数据，与其他用例的覆写方式一致（同类做法见 T67/T68 的 `dispatchStripped`）。
- **绿端证据**：`fix:` 提交 `b7da45e`（仅 `HomeView.vue`）→ `HomeView.spec.ts` **17 passed**；全量 `npx vitest run` = **303 passed (303)**（原 301 + 新增 2，零回归）；`npm run build`（含 vue-tsc）= **✓ built in 652ms**。
- **实现**：`v-if="previewsFor(store).length >= 3"` 挂在渐隐元素上，并在模板注释里写明「渐隐用于暗示右侧还有更多商品，不足三张仍渲染会被误认为裁切（SHOW-QA-005）」；未改动商品数量聚合（仍为每卡最多 3 个）与任何样式值。
- **未收口**：① 分支未开 PR（需 review 后合并）；② **视觉确认待补**——本缺陷属几何/视觉类，jsdom 无布局引擎，按 `前端架构设计与工程约定` §6 的既有口径，最终以真机或 E2E 截图对照（2 张店铺 vs 3 张店铺）为准，问题记录里也提到需先确认种子中是否存在「商品图 2 张」的店铺（本次用替身构造）；③ 缺陷台账 `SHOW-QA-005` 的状态流转（新建 → 待回归 → 已关闭）写权归测试联调同学，本轮未改台账。
